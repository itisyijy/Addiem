## A. 되돌리기 비싼 것 — 먼저 봐줬으면 하는 것

### A1. ~~하지 않은 일: Rust 툴체인 설치~~ — 해결됨 (2026-10-14)

작성자 요청으로 개발 환경을 구축하면서 설치했다. Rust 1.99.0, `rust-toolchain.toml` 로 고정. README의 "개발 환경" 참고.

아래는 당시 기록이다.

Rust와 Cargo가 설치되어 있지 않다. Tauri 앱을 만들려면 필요하다.

**설치하지 않았다.** PATH와 홈 디렉터리를 건드리는 시스템 변경이라 자리에 없을 때 임의로 할 일이 아니라고 판단했다.

돌아오면 이걸 실행하면 된다.

```bash
winget install Rustlang.Rustup
```

이것 때문에 이번에 앱 코드는 만들지 못했다. 대신 **언어와 무관한 부분**(스키마, 매핑 규칙, 큐 알고리즘)을 확정하고 Python으로 검증해두었다. Rust 구현은 옮기기만 하면 된다.

### A2. 중요도 태그 매핑을 순위 보존으로 정했다

실측 컬렉션의 `중요도::` 3단계를 우리 3단계에 1:1로 대응시켰다.

| Anki 태그 | 개수 | → Neo-Anki |
|---|---|---|
| `중요도::최우선` | 1,388 | 핵심 |
| `중요도::높음` | 940 | 일반 |
| `중요도::보통` | 114 | 보충 |

**판단.** 순위를 보존하는 게 가장 예측 가능하다. 큐 정렬이 쓰는 건 순서지 이름이 아니다.

**이견이 있을 만한 지점.** `보통 → 보충`은 어감이 어긋난다. "보통"인 카드를 "보충(덜 중요)"으로 내리는 게 맞는가? 대안은 `최우선+높음 → 핵심, 보통 → 일반`인데, 그러면 핵심이 2,328장(전체의 50%)이 되어 우선순위의 의미가 약해진다.

### A3. `star3`을 핵심으로 올렸다

| 태그 | 개수 | → |
|---|---|---|
| `star4` | 12 | 핵심 |
| `star3` | 420 | **핵심** |
| `star2` | 192 | 일반 |
| `star1` | 177 | 보충 |

**판단.** 4단계를 3단계로 접으려면 어딘가에서 합쳐야 하고, 위쪽을 합쳤다.

**이견이 있을 만한 지점.** `star3`을 일반으로 내리면 핵심이 1,709 → 1,300 정도로 줄어든다. 이 태그가 무슨 의미로 붙은 건지는 작성자만 안다.

### A4. 삭제된 카드의 복습 기록을 보존한다

실측에서 7,745건 중 **1,310건(17%)이 이미 삭제된 카드의 기록**이었다. 이걸 `card_id = NULL`로 남긴다.

**판단.** 학습 히트맵과 "그날 얼마나 공부했나"는 카드가 사라져도 사실로 남아야 한다. 스키마에 `ON DELETE SET NULL`로 설계한 것과도 일관된다.

**이견이 있을 만한 지점.** 카드에 연결되지 않는 기록이 17%나 쌓인다. 통계에서 이걸 포함할지 제외할지는 화면마다 다르게 정해야 한다.

### A5. `보류된 2회차 Again`을 기록하되 스케줄러에는 넘기지 않는다

`review_log.fed_to_scheduler` 컬럼을 두었다.

**판단.** 이전에 제안하고 동의받지 못한 항목이다. 기록 손실 없이 큐가 통제권을 갖는다.

[스파이크 5](engineering/spike-05-fsrs.md)에서 FSRS가 이 방식을 허용함을 확인했다 — `review_card`를 호출하지 않으면 카드 상태가 그대로 유지된다. **ADR 0001 7장을 "확인됨, 승인 대기" 상태로 채워두었다. 승인만 하면 된다.**

### A6. 신규 카드 예산을 하위 덱마다 주지 않는다

**실제 데이터에서 발견했다.** 실측 컬렉션은 덱이 140개(대부분 하위 덱)다. 하위 덱마다 하루 20장을 주면 오늘 신규가 **1,699장**이 된다.

```text
규칙: 신규 예산은 설정을 가진 가장 가까운 조상 덱이 갖는다.
      아무도 설정이 없으면 최상위 덱이 갖는다.
```

같은 데이터에서 100장이 되었다.

**이견이 있을 만한 지점.** 하위 덱별로 세밀하게 조절하고 싶은 경우 그 덱에 설정을 직접 주어야 한다. 기본 동작이 "상위에서 통제"인 것이 맞는지 판단이 필요하다.

### A7. FSRS로 확정했다

[스파이크 5](engineering/spike-05-fsrs.md) 결과 네 조건을 모두 만족했다. 라이선스 MIT, 4등급 그대로, 덱별 파라미터 가능, 학습 단계는 라이브러리 관리.

**Python 구현으로 확인했다.** Rust 툴체인이 없어서다(A1). 같은 조직의 같은 알고리즘이라 답은 옮겨지지만 `fsrs-rs`의 실제 시그니처는 재확인이 필요하다.

**부수 결정.** 테스트에서는 `enable_fuzzing`을 끈다. 같은 입력에 다른 결과가 나오면 큐 테스트가 성립하지 않는다.

## B. 스키마 설계

`db/schema.sql` 이 정본이다. **B10과 B11은 스파이크 5에서 찾아낸 결함을 고친 것이라 되돌리면 안 된다.**

| # | 결정 | 근거 |
|---|---|---|
| B1 | 시각은 UTC epoch **밀리초** 정수 | Anki는 초와 밀리초를 섞어 쓴다. 하나로 통일했다 |
| B2 | 중요도는 **정수 0/1/2** | 큐가 이 값으로 정렬한다. 텍스트면 매번 CASE가 필요하다 |
| B3 | `note.fields`는 **JSON 배열** | Anki는 `\x1f` 구분 문자열이다. JSON이 디버깅과 쿼리 모두 낫다 |
| B4 | `note.tags`는 **문자열 그대로** (정규화 안 함) | MVP에 태그 검색이 없다. 필요해지면 그때 테이블로 뺀다 |
| B5 | 학습일을 **컬럼으로 저장하지 않는다** | 시각에서 파생한다. 하루 경계 설정이 바뀌면 과거가 통째로 틀어진다 |
| B6 | `card_effective` **뷰**로 중요도 상속 | 카드 값이 NULL이면 덱 값을 쓴다. 매 쿼리에 COALESCE를 쓰지 않는다 |
| B7 | `deck`에 `UNIQUE(parent_id, name)` | 같은 부모 아래 같은 이름 덱을 막는다 |
| B8 | 노트 삭제 시 카드 **CASCADE**, 복습 기록은 **SET NULL** | A4 참고 |
| B9 | 하루 경계를 `schema_meta`에 저장 (기본 4시) | 나중에 설정 화면에서 바꿀 수 있다 |
| **B10** | **보류를 `state` 값이 아니라 `buried_until` 기간으로** | 상태로 덮으면 보류 전이 review였는지 learning이었는지 잃는다. 스파이크 5에서 발견 |
| **B11** | **`card.srs_step` 추가** | FSRS의 learning 단계 위치. 없으면 앱 재시작 시 학습 중 카드가 처음 단계로 되돌아간다 |

## E3. 와이어프레임 브리프는 1장만 채웠다

74개 TODO 중 1장(홈 정보 우선순위)만 채우고 나머지는 비워두었다.

**판단.** 화면별 브리프는 코드로 대신하는 편이 낫다고 이전에 제안했고 결론이 안 났다. 다만 **1장은 코드로 대신할 수 없는 제품 결정**이라 채웠다. 홈에 뭘 먼저 보여줄지를 안 정하면 어떤 화면을 만들어도 다시 만든다.

정한 것 중 논의가 필요할 만한 것.

| 결정 | 이견 가능성 |
|---|---|
| 홈은 오늘의 학습 화면이다. 덱 목록이 아니다 | 화면 흐름 문서가 이미 그렇게 정했다. 확인만 |
| 밀린 카드를 홈 합계에 섞지 않는다 | 밀린 양을 숨기는 것처럼 느낄 수 있다 |
| 홈에 하위 덱을 펼치지 않는다 | 실측 140개 덱이 근거다. 최상위 7개만 보인다 |

| **I74** | **보내는 것은 사용자가 누른 카드 한 장의 질문 글자와 번호 붙인 답 항목 글자뿐이다** (규칙 분할과 같은 글자: HTML·그림·`[sound:]` 를 뺀 화면 글자). 덱 이름·다른 카드·복습 기록·일정·원자료·그림은 보내지 않는다. `store: false`. 모델은 카드마다 질문과 항목 **번호**만 돌려주고, 답은 원래 항목 글자를 그대로 쓴다 (답 내용을 지어낼 수 없다). 60항목·6,000자가 넘으면 보내지 않는다. 처음 보낼 때 한 번 묻고(이 기기 `localStorage`), 연결을 끊으면 다시 묻는다 | 번호만 받으면 "표현을 다듬어 주는" 쪽은 못 한다. 대신 원문 보존이 확실하다 |
| I75 | 토큰: 새로 고칠 토큰만 OS 키체인(`chatgpt-refresh-token`, 동기화와 같은 서비스 이름), 접근 토큰은 메모리에만. 저장하기 전에 ID 토큰을 OpenAI JWKS 로 RS256 서명 확인(`ring` 0.17.14 — rustls 가 이미 쓰는 것이라 새로 받는 크레이트 없음) + `iss`·`aud`(발급받은 client_id)·`exp`·`nonce`, 그리고 받은 권한에 `chatgpt.tokens.use.direct` 가 있는지 본다. 없으면 저장하지 않고 폐기한다 ("사용량 권한이 필요해요" → [다시 연결]은 `prompt=consent`). 모델 목록이 "대상 요금제 아님"이면 연결하지 않는다. `schema_meta`(동기화 안 함): `ai_host_id`·`ai_client_id`·`ai_sub`·`ai_email`·`ai_model`·`ai_sent`(이번 달 보낸 수)·`ai_sent_at`·`ai_welcomed`. [연결 끊기]는 확인 없이 바로: 진행 중인 요청을 멈추고 `revocation_endpoint` 로 폐기 + 키체인 삭제. 등록(client_id)·host id 는 남긴다 | 문서는 사용량 권한이 빠져도 로그인은 남겨 두라고 하지만, 다른 결제 경로가 없어 연결하지 않는 쪽을 골랐다 (Figma L2-x). 백업을 다른 기기에 복원하면 host id 가 같아진다 |
| I76 | 모델: `GET /v1/models` 의 `visibility == "list"` 만, 서버 순서를 지키되 이름에 `mini` 가 든 것을 앞으로 (작은 모델로 충분). 연결할 때 하나 골라 두고, 쓸 수 없다고 하면 목록의 다음 모델. 출력은 `text.format` json_schema(strict)로 먼저, 받지 않으면(`unsupported_capability`·`text`) 형식 없이 한 번 더. 스트림은 `response.completed` 일 때만 성공이고 `response.failed`·`response.incomplete`·`error`·끊김을 따로 다룬다 | 이름으로 고르는 어림이다 (코드에 ponytail 표시). 모델 고르기 화면은 없다 |
| I77 | 실패는 언제나 규칙 분할로 돌아갈 수 있다. 형식 검사(2–8장, 빈 질문 없음, 모든 항목 정확히 한 번)를 하나라도 어기면 깨진 응답은 한 조각도 쓰지 않고 규칙 제안 + 노란 안내 + [다시 묶기]. 사용량 한도(`subscription_sharing_usage_limit_exceeded`, 스트림 중간에도 온다)는 [사용량 관리]가 첫 버튼이고 다른 결제로 넘기지 않는다. 401 은 토큰을 한 번 새로 받아 다시 보내고, 새로 고치기가 끝내 거절(`invalid_grant`·`refresh_token_*`)되면 다시 로그인. 네트워크·5xx 로는 토큰을 지우지 않는다. 보낸 카드 수는 이 기기에서만 세고 사용량 추정은 보이지 않는다 | 브리프의 "2–6장, 항목은 최대 한 번"보다 엄격하다 (디자인 L5: 누락 없음, 2–8장) |

## K. Google Drive 보관·동기화 설계 (8.6 Later, 2026-10-14)

작성자 요청으로 화면(Figma Row K, K0–K10)과 [설계 문서](engineering/drive-sync.md)를 먼저 만들었고, 이어 구현했다 (K10~K19는 구현하면서 정한 것. 실제 Google 계정 확인은 아직). **굵게** 표시한 것은 되돌리기 비싸거나 기존 문서와 다른 것이다.

| # | 결정 | 이견 가능성 |
|---|---|---|
| **K1** | **Neo-Anki 서버 없이 사용자의 Drive를 저장소로 쓴다.** 합치는 일은 각 기기가 같은 규칙으로 한다 | 제품 방향의 "Neo-Anki 기본 동기화 서버" 선택지와 다르다. 서버가 없으면 계정·운영비가 없는 대신 합치기 로직이 클라이언트에 들어간다 |
| K2 | 권한은 `drive.file` + `drive.appdata` 두 개. 동기화 데이터는 숨김 공간, 백업 zip만 보이는 폴더에 둔다 | 사용자가 동기화 데이터를 직접 볼 수 없다. 대신 실수로 지우거나 고쳐서 깨뜨릴 수 없다 |
| K3 | Drive 백업 zip에는 그림을 넣지 않는다 (그림은 `media/` 에 한 번만) | 이 기기 백업(I19, 그림 포함)과 형식이 다르다. 넣으면 백업 12개가 약 4GB가 된다 |
| K4 | 카드 내용 충돌은 나중 것으로 자동으로 맞추고, 진 쪽은 기록에 남긴 뒤 토스트로 알린다 (K7) | 매번 사용자에게 묻는 방식도 있다. 학습 흐름을 멈추지 않는 쪽을 골랐다 |
| K5 | 암호로 잠그기는 **기본 꺼짐** | 프라이버시만 보면 기본 켜짐이 낫다. 비밀번호를 잊으면 Drive 쪽은 복구할 수 없어서 선택으로 두었다 |
| K6 | 원자료 파일(8.4)은 기본으로 올리지 않는다. 분석 모델은 절대 올리지 않는다 | 원자료가 없으면 두 번째 기기에서 원자료 패널(I2)이 비어 있다 |
| K7 | 학습 중에는 동기화하지 않는다. 창을 닫을 때는 최대 10초 올리고 닫는다 (K8) | 학습 중 실시간 동기화를 기대할 수 있다 |
| **K8** | **동기화하려면 스키마 선행 작업이 필요하다**: 동기화 대상 테이블에 `uid`(ULID), 삭제 기록 `sync_tombstone`, 변경 기록 `sync_outbox`(트리거), 기기 id, HLC | **8.6을 언제 하든 `uid` 는 일찍 넣을수록 싸다.** 사용자 데이터가 쌓인 뒤에는 모든 기존 행에 uid를 채우는 마이그레이션이 필요하다 |
| K9 | I3 배너·Row I 문구 "자료와 카드는 기기 밖으로 나가지 않아요"를 "분석하려고 자료와 카드를 밖으로 보내지 않아요"로 바꿨다 | Drive를 켜면 사용자 자신의 Drive로는 올라가므로 앞 문장은 틀린 말이 된다 |

| K17 | 잠그기를 켜고 끄면 새 세대로 다시 올리고 지난 세대 파일은 지운다. 잠근 동안 Drive 백업 zip도 암호화. `devices/*.json` 은 평문(이름·숫자·시각) | 잠그기 전 보이는 백업은 평문으로 남는다 |
| K18 | 개발용 `NEOANKI_SYNC_FOLDER` (로그인 없이 로컬 폴더를 Drive처럼) | 개발 전용 |

## L. 외부 AI · ChatGPT로 연결 (2026-10-15)

구현 세션 요청으로 Figma Row L(L1–L4-e, 라이트·다크)을 그렸다. 작성자가 API 키가 아니라 요금제 계정 로그인을 원했다고 전달받았다. **굵게** 표시한 것은 기존 원칙과 다른 것이다.

| # | 결정 | 이견 가능성 |
|---|---|---|
| **L1** | **선택 기능으로 외부 AI를 연다.** 제품 방향은 "LLM API 없이 동작"이었다. 범위는 카드 나누기(G2)의 "성격별로 묶기" 하나, 보내는 것은 직접 누른 카드 한 장의 앞·뒷면 글자뿐, 기본은 꺼짐 | **사용자 승인 (2026-10-15).** 외부 LLM은 선택 기능이고 필수 핵심 기능으로 두지 않는다는 9장 원칙은 그대로다. 다른 기능에 쓸 때마다 보내는 범위를 같은 수준으로 다시 정한다 |
| L2 | OpenAI "Sign in with ChatGPT"만 넣는다. Claude·Gemini 자리나 "준비 중" 항목도 두지 않는다 | 둘 다 외부 앱 구독 로그인이 정책상 막혀 있다 |
| L3 | 로그인 버튼은 영어 "Continue with ChatGPT" + OpenAI 공식 로고 자산 그대로. 나머지 문구는 한국어 ("ChatGPT 요금제 사용", "사용량 관리", "내 ChatGPT 요금제를 쓰고 있어요") | 버튼까지 한국어로 옮길 수도 있다. 브랜드 표식이라 가이드 문구를 지켰다 |
| L4 | "ChatGPT를 연결하면 직접 누른 카드만 OpenAI로 보내요"는 L1 사실 칸과 L2 시트에만. 설정의 백업·데이터 삭제 칸에는 넣지 않는다. I3 문구는 그대로 | 그 칸들은 기기 안의 일이다 |
| L6 | **타사 이미지는 모두 공식 자료를 쓴다** (사용자 원칙, 2026-10-15). ChatGPT 로고는 OpenAI 공식 버튼 자산(`src/assets/brand/chatgpt-logo-{white,black}.svg`), 밝게는 검정 버튼에 흰 로고, 다크는 흰 버튼에 검정 로고. Figma 전체를 검사한 결과 다른 타사 로고는 그린 곳이 없다: Google Drive는 일반 구름 아이콘, Anki는 일반 가져오기 아이콘 + 이름 글자만 | Google·Anki 공식 표식을 쓰려면 각 사의 브랜드 사용 규정을 따로 확인해야 한다. 지금은 쓰지 않는다 |
| L5 | 결과는 자동 적용하지 않는다. Rust에서 형식 검증을 통과한 것만 편집 가능한 목록으로 보여주고, 깨지면 규칙 분할로 돌아간다 | 검증 기준(2–8장, 빈 면 없음, 원래 항목 누락 없음)은 구현에서 조정 |

## R. 자료 근거 AI (RAG) (2026-10-15)

구현 세션 요청으로 Figma Row R(R1-a–R3-s, 라이트·다크)을 그렸다. 찾기는 기기 안(e5-small · source_segment · source_link), ChatGPT는 글을 만들 때만 쓴다. Claude(MCP)는 나중.

| # | 결정 | 이견 가능성 |
|---|---|---|
| **R1** | **보내는 범위를 "직접 고른 카드와 자료 구간"으로 넓혔다.** L1·L2 문구도 바꿨다 ("직접 고른 카드와 자료 구간만 OpenAI로 보내요"). 자료 파일 통째·그림·다른 카드·복습 기록·덱 이름은 보내지 않는다 | L1(카드 한 장)보다 넓다. 구간 글은 원문 그대로, 1구간 600자에서 자른다 |
| R2 | 보내는 범위 한 줄("… N구간을 보내요 · 보기")은 실행 버튼 아래에 늘 보인다. 사용자가 구간을 고르는 기능(R1)은 매번 목록을 펼쳐 보낸다. 앱이 구간을 고르는 기능(R2·R3)은 처음 한 번(채점 보조는 학습 세션마다 한 번) 목록을 펼쳐 확인받는다 | 매번 확인하면 학습 흐름이 끊기고, 한 번도 안 보이면 범위를 모른다. 그 사이로 정했다 |
| R3 | 빠진 범위(R1-a)는 기기 안에서 계산하고 연결 없이 된다. 입구는 자료 화면 세그먼트와 덱 상세의 [자료 N] 숫자 | 원자료 패널(I2)에는 넣지 않았다 |
| R4 | 초안(R1-c)은 기기 안에서 두 가지를 검사한다: 비슷한 카드(유사도 0.88 이상, 기본 체크 끔), 근거에 없는 말(낮은 유사도 문장 표시) | 검사 기준은 구현에서 조정 |
| R5 | 채점 보조 단축키 G. 결과가 오기 전에 평가하면 요청을 취소한다. 추천은 핵심어 검사와 합쳐 한 줄로 | E4 표 겹침 검사 필요 |

## P. 시험 전 회독 · 혼합 (8.5, 2026-10-15)

작성자 결정으로 시작. Figma Row P(P0–P3, 라이트·다크).

| # | 결정 | 이견 가능성 |

| P6 | 입구 3곳(목표일 14일 전부터): 홈 덱 목록 위 한 줄, 덱 상세 목표 카드, 학습 계획(H1) 마지막 주 줄 | |
