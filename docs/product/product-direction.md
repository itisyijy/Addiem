# Neo-Anki 제품 방향

## 한 문장 정의

Neo-Anki는 시험 목표와 카드 품질을 함께 관리해, 사용자가 제한된 시간 안에 핵심 내용을 효율적으로 암기하도록 돕는 Anki 호환 학습 시스템이다.

## 제품 문장

> Anki가 복습 시점을 관리한다면, Neo-Anki는 시험일까지의 완주 전략을 관리한다.

## 문제 정의

Anki는 장기적인 반복 주기 관리에는 뛰어나지만, 시험 중심 사용자에게 중요한 다음 문제를 충분히 다루지 못한다.

- 시험이라는 명확한 데드라인
- 카드별 중요도 차이
- AI 생성 카드의 품질 편차
- 긴 서술형 답변의 자기 채점 부담
- 어려운 카드가 신규 진도를 막는 문제
- 전체 범위를 끝낼 수 있는지에 대한 가시성 부족

기존 Anki의 중심 질문은 다음과 같다.

> 이 카드를 언제 다시 보여줄 것인가?

Neo-Anki가 추가로 해결해야 할 질문은 다음과 같다.

- 시험일까지 무엇을 우선적으로 학습해야 하는가?
- 계속 틀리는 이유가 기억 부족인가, 카드 품질 문제인가?
- 어려운 카드가 전체 진도를 막지 않게 어떻게 관리할 것인가?
- 서술형 답변을 자신의 언어로 설명했을 때 어떻게 부담 없이 평가할 것인가?
- 자동화된 변경을 사용자가 어떻게 이해하고 통제할 것인가?

## 제품 가설

카드의 품질과 중요도를 분석하고 시험일까지의 학습 계획을 능동적으로 조정하면, 사용자는 더 적은 피로로 핵심 범위를 완주하고 자신의 시험 준비 상태를 명확하게 파악할 수 있다.

## 핵심 가치

### 시험일까지 핵심 범위를 완주한다

오늘 복습할 카드를 나열하는 데서 끝나지 않고, 남은 기간 안에 전체 범위를 학습할 수 있도록 계획한다.

### 어려운 카드 하나가 전체 진도를 막지 않는다

반복 실패 카드는 다시 보여주되 신규 범위 학습을 방해하지 않도록 별도 흐름으로 관리한다.

### 카드 품질 문제를 사용자 기억력 문제로만 취급하지 않는다

계속 틀리는 카드가 너무 길거나 복잡한지 진단하고, 반복보다 재구성이 필요한 경우를 구분한다.

### 서술형 답변을 의미 중심으로 평가한다

정답 문장과 완전히 일치하지 않아도 핵심 키워드, 관계, 설명이 의미상 일치하는지 판단하도록 돕는다.

### 자동화와 사용자 통제를 함께 제공한다

추천과 자동화를 제공하되, 변경 전 제안, 이유 설명, 승인, 변경 이력, 되돌리기를 보장한다.

## 설계 원칙

### Goal-driven

덱을 만들거나 가져올 때 시험일, 시험 유형, 목표 범위를 함께 설정한다.

### Anki-compatible

Anki 덱 호환성을 유지하고 기존 사용자의 자산을 그대로 가져갈 수 있어야 한다.

### SRS-preserving

검증된 SRS를 대체하기보다 데드라인, 중요도, 진도 관리 계층을 추가한다.

### Local-first

핵심 기능은 외부 LLM API 없이 로컬에서 동작하는 방향을 우선한다.

### Sync-only server

서버는 AnkiWeb처럼 카드, 자료, 진행 상황 동기화에 집중한다.

### User-controlled automation

사용자가 언제든 범위, 순서, 일정, 카드 내용을 직접 조정할 수 있어야 한다.

### Explainable changes

우선순위 변경, 카드 분해, 일정 재계산의 이유를 짧고 명확하게 설명한다.

### Reversible changes

카드와 덱의 변경을 버전 또는 커밋 단위로 기록하고 이전 상태로 복구할 수 있어야 한다.

### Low cognitive overhead

세밀한 점수 입력이나 복잡한 설정을 강요하지 않는다. Again, Hard, Good, Easy처럼 직관적인 상호작용을 유지한다.

### Source-linked learning

카드가 어렵거나 불명확할 때 원본 슬라이드, 필기, 이미지, 생성 근거로 돌아갈 수 있어야 한다.

## 핵심 사용자 흐름

### 대학 서술형 시험

1. 강의 PDF와 필기자료를 등록한다.
2. 시험일과 서술형 시험 유형을 설정한다.
3. 자료의 강조 표시, 목차, 기출 이력을 바탕으로 중요도를 제안한다.
4. Import된 카드 중 길고 복잡한 카드를 표시한다.
5. 사용자가 카드 분해 또는 단순화 제안을 검토한다.
6. 핵심 개념부터 1차 회독한다.
7. 반복 실패 카드는 별도 큐로 이동해 신규 진도를 막지 않게 한다.
8. 시험 직전에는 전체 범위를 압축해서 확인하되 취약 카드와 중요 카드를 더 자주 보여준다.
9. 준비도, 숙달률, 취약 범위, 예상 완료일을 확인한다.

### 자격증 시험

1. 기존 Anki 덱 또는 외부 자료 기반 덱을 Import한다.
2. 시험일과 객관식 시험 유형을 설정한다.
3. 기출 이력이 있는 카드를 높은 우선순위로 설정한다.
4. 핵심 카드 중심으로 전체 범위를 빠르게 학습한다.
5. 시험이 가까워질수록 신규 카드와 복습 카드 비중을 재조정한다.
6. 취득 후 덱을 보관하거나 공유 덱으로 전환한다.

| 중요한 카드와 세부 카드가 섞임 | 핵심부터 학습 | 카드 우선순위와 단계별 회독 |
| 특정 카드가 반복되어 진도가 막힘 | 어려운 카드 보류 | 반복 루프 방지와 별도 큐 |
| 긴 카드가 머리에 들어오지 않음 | 자동 재구성 | 긴 카드 분해 제안 |

| 서술형 채점이 피곤함 | 의미 중심 평가 | 키워드와 관계 기반 채점 보조 |
| 시험 직전 전체를 보고 싶음 | 전체와 취약점 동시 확인 | 압축 회독 모드 |
| 카드 수정이 불안함 | 되돌리기 | 카드 버전 관리 |
| 학습 현황을 파악하기 어려움 | 목표 중심 통계 | 시험 준비도 대시보드 |
| 공동 덱 품질이 불안함 | 검토 절차 | PR 방식 카드 제안과 승인 |

## MVP 제안

### MVP 1. 시험 목표와 스케줄링

- 시험일 설정
- 시험 유형 설정
- 핵심 범위와 전체 범위 구분
- 일별 신규 카드와 복습 카드 계획
- 일정 변경 시 자동 재계산
- 사용자의 수동 범위와 순서 조정

### MVP 2. 우선순위 기반 학습

- 카드 중요도 설정
- 핵심 카드 우선 회독
- 1순위 학습 후 2순위 세부 학습
- 중요도별 필터 학습
- 시험 직전 압축 회독

### MVP 3. 어려운 카드 관리

- 반복 실패 카드 자동 감지
- 잠시 보류 후 재등장
- 신규 카드 진도를 방해하지 않는 별도 큐
- 반복이 필요한 카드와 재구성이 필요한 카드 구분
- 카드 분해 또는 단순화 제안

### MVP 4. 카드 품질 진단

- 답변 길이가 지나치게 긴 카드 탐지
- 하나의 질문에 여러 내용을 요구하는 카드 탐지
- 질문과 답변 구조가 불명확한 카드 탐지
- 개행과 번호 등 기본 서식 제안
- 카드 분해 또는 단순화 제안

### MVP 5. 시험 준비도 대시보드

- 시험까지 남은 날짜
- 전체 범위 학습률
- 핵심 범위 숙달률
- 아직 보지 않은 카드
- 계속 틀리는 카드
- 취약 챕터
- 예상 완료일
- 일별 학습 히트맵

## 후순위 확장

### 서술형 채점 보조

초기에는 카드 작성자가 필수 키워드와 평가 기준을 지정하는 방식으로 시작할 수 있다.

이후 로컬 임베딩이나 로컬 언어 모델을 활용해 다음을 보조할 수 있다.

- 필수 키워드 포함 여부
- 핵심 관계 설명 여부
- 누락된 주요 내용
- 잘못 연결한 개념
- 자신의 언어로 설명했는지

### 원자료 기반 보충 세션

반복 실패 카드에 대해 다음 자료를 다시 제시한다.

- 원본 슬라이드
- 관련 이미지
- 카드가 생성된 문단
- 사용자 필기
- 보충 설명

### 이미지 카드 편집

- 이미지 크기 자동 조정
- 텍스트와 이미지 영역 분리
- 이미지 일부 가리기
- 빈칸 생성
- 영역 선택형 문제 제작

### 공동 덱과 버전 관리

- 다른 사용자의 덱 복사
- 개인 수정본 유지
- 원본 덱에 수정 제안
- 관리자 검토와 승인
- 카드 변경 이력
- 버전별 복구

### 동기화 옵션

- Neo-Anki 기본 동기화 서버
- 개인 클라우드 저장소
- Google Drive
- GitHub 저장소
- 로컬 파일 기반 백업

## 범위에서 주의할 점

### LLM 기능을 제품 중심으로 두지 않는다

Neo-Anki의 핵심은 카드 자동 생성 자체가 아니라, 시험일까지의 완주, 카드 품질 관리, 학습 우선순위, 복습 피로 감소다.

### 협업 기능을 MVP에 과도하게 넣지 않는다

공동 덱과 PR형 검토는 매력적이지만 UI 복잡도가 빠르게 증가할 수 있다.

### 새로운 SRS를 먼저 만들지 않는다

초기에는 기존 Anki 호환성과 검증된 스케줄링을 유지하고, 목표 기반 orchestration에 집중한다.

## 현재 검증 상태

이 문서는 한 명의 숙련 Anki 사용자에 대한 심층 인터뷰를 바탕으로 작성되었다.

다음 사용자군을 추가 인터뷰해 공통 문제와 개인 선호를 분리해야 한다.

- Anki 초보 사용자
- 장기 언어 학습자
- 의학, 법학 등 대규모 장기 암기 사용자
- 공유 덱 중심 사용자
- 모바일 중심 사용자
- 시험 직전 벼락치기 사용자
