# Neo-Anki MVP 범위

## 문서 상태

- 버전: v0.1 초안
- 목적: 첫 구현에서 검증할 제품 가설과 기능 경계를 고정한다.
- 기준: 이 문서의 `Must`만으로 핵심 사용자 흐름이 끝까지 동작해야 한다.
- 전제: 현재 방향은 한 명의 숙련 Anki 사용자 인터뷰와 이후 제품 논의를 바탕으로 한 가설이다.

## 1. 제품 정의

Neo-Anki는 기존 Anki 사용자와 플래시카드 경험이 없는 사용자 모두가 사용할 수 있는 목표 기반 반복 학습 앱이다.

> 기존 사용자는 Anki 덱을 이어서 사용하고, 신규 사용자는 새 덱을 만든다. 각 덱은 필요에 따라 목표일과 학습 전략을 가지며, Neo-Anki는 오늘 무엇을 먼저 학습할지 구성한다.

### MVP 한 문장

> 새 덱을 만들거나 Anki 덱을 가져온 사용자가, 덱별 목표와 카드 중요도에 맞춰 오늘의 학습 계획을 받고, 어려운 카드에 전체 진도가 막히지 않도록 복습할 수 있는 로컬 데스크톱 앱

## 2. 검증할 핵심 가설

> 덱별 목표와 카드 우선순위를 반영해 오늘의 학습 큐를 구성하고, 반복 실패 카드를 현재 흐름에서 잠시 분리하면 사용자는 제한된 기간 안에 더 넓은 범위를 안정적으로 학습할 수 있다.

MVP는 다음 두 가치를 검증한다.

1. **목표일까지 필요한 범위를 완주하도록 돕는가**
2. **어려운 카드가 전체 진도를 막지 않게 하는가**

단순히 덱을 만들고 카드를 반복하는 기능만으로는 Neo-Anki의 가설을 검증할 수 없다.

## 3. 타깃 사용자

### 기존 Anki 사용자

- 기존 `.apkg` 덱을 가지고 있다.
- 익숙한 질문-답변 방식과 Again / Hard / Good / Easy 평가를 유지하고 싶다.
- 기존 덱 자산을 버리지 않고 목표 기반 계획 기능만 추가로 사용하고 싶다.

### 신규 사용자

- Anki, SRS, FSRS, 노트 타입 등의 용어를 모를 수 있다.
- 설명이나 긴 온보딩보다 바로 덱을 만들고 카드를 학습하기를 원한다.
- 앱이 복습 원리를 대신 처리하고, 자신은 오늘 할 학습에 집중하기를 원한다.

### 공통 특성

- 하나의 공부만 하지 않는다.
- 시험, 자격증, 영단어처럼 성격이 다른 여러 덱을 동시에 운영할 수 있다.
- 학습 특성은 사용자 전체가 아니라 **덱별로 달라진다.**

## 4. 경험 설계 원칙

### 온보딩을 강제하지 않는다

첫 실행 시 사용자 유형, 학습 목적, 시험 유형을 묻지 않는다. 사용자는 즉시 홈으로 들어가 새 덱을 만들거나 Anki 덱을 가져온다.

### 첫 행동이 사용법을 설명한다

별도의 서비스 소개 슬라이드 대신, 빈 홈과 명확한 행동 버튼으로 시작한다.

- 새 덱 만들기
- Anki 덱 가져오기

### 덱별 설정을 사용한다

다음 항목은 사용자 전역 설정이 아니라 덱 설정이다.

- 목표일
- 카드 중요도
- 일일 학습량 상한
- 학습 범위
- 이후 추가될 시험 유형과 채점 방식

### 점진적으로 기능을 노출한다

목표일과 고급 학습 설정은 덱 생성 전에 강제하지 않는다. 덱을 만든 뒤 해당 기능이 유용해지는 시점에 제안한다.

### 자동화는 설명 가능하고 수정 가능해야 한다

오늘의 학습량과 카드 순서를 자동으로 구성하더라도 사용자가 분량과 범위를 조정할 수 있어야 한다.

## 5. 범위 분류 기준

| 구분 | 의미 |
|---|---|
| Must | MVP가 제품 가설을 검증하기 위해 반드시 필요하다. |
| Should | MVP 이후 공개 베타 전까지 우선 검토한다. 없어도 핵심 흐름은 작동한다. |
| Later | 핵심 학습 루프가 검증된 뒤 확장한다. |
| Out | 현재 제품 방향과 맞지 않거나 당분간 개발하지 않는다. |

# 6. Must: MVP 필수 범위

## 6.1 즉시 진입 가능한 홈

### 기능

- 별도의 필수 온보딩 없이 홈으로 진입한다.
- 덱이 없으면 빈 상태를 표시한다.
- `새 덱 만들기`와 `Anki 덱 가져오기`를 바로 찾을 수 있다.
- 덱이 있으면 오늘 학습할 전체 카드 수와 덱별 학습량을 보여준다.
- 홈에서 전체 학습 또는 특정 덱 학습을 시작할 수 있다.

### 빈 상태 예시

```text
Neo-Anki

아직 학습할 덱이 없습니다.

[새 덱 만들기]   [Anki 덱 가져오기]
```

### 완료 조건

- 신규 사용자가 별도 설명 없이 덱 생성 경로를 찾을 수 있다.
- 기존 사용자가 홈에서 Anki 가져오기 경로를 찾을 수 있다.
- 덱이 있는 사용자가 홈에서 한 번의 주요 행동으로 학습을 시작할 수 있다.

## 6.2 덱 생성과 기본 관리

### 기능

- 덱 이름만 입력해 새 덱을 만든다.
- 여러 덱을 생성할 수 있다.
- 덱 이름 변경, 보관, 삭제가 가능하다.
- 덱별 카드 목록을 확인할 수 있다.
- 덱 생성 시 목표일이나 시험 유형을 필수로 묻지 않는다.

### 완료 조건

- 사용자가 덱 이름 하나만 입력하고 학습 공간을 생성할 수 있다.
- 서로 다른 성격의 덱을 독립적으로 관리할 수 있다.

## 6.3 기본 카드 생성과 편집

### 네이티브 생성 범위

- 질문과 답변 카드
- 빈칸 카드
- 기본 텍스트 서식
- 이미지 한 개 이상 첨부
- 카드 생성, 수정, 삭제
- 카드 검색

카드 유형은 이후 별도 설계 문서에서 확장한다. MVP에서는 신규 사용자가 즉시 만들고 학습할 수 있는 최소 유형만 지원한다.

### 기본 동작

- 카드 유형을 선택하지 않으면 질문과 답변 카드가 기본값이다.
- 카드 작성 중 고급 설정을 강제하지 않는다.

### 완료 조건

- 사용자가 새 덱을 만든 뒤 첫 카드를 추가하고 즉시 학습할 수 있다.
- 카드의 질문, 답변, 이미지를 수정하거나 삭제할 수 있다.

## 6.4 Anki 덱 가져오기

### 지원 대상

- `.apkg` 파일 선택
- 덱과 하위 덱 구조
- Basic
- Basic and Reversed
- Cloze
- 기본 HTML 텍스트
- 기본 이미지와 미디어

### 가져오기 원칙

- 지원하지 않는 항목을 조용히 삭제하거나 변환하지 않는다.
- 가져오기 완료 후 다음을 알려준다.
  - 가져온 덱 수
  - 가져온 카드 수
  - 정상적으로 처리하지 못한 카드 수
  - 확인이 필요한 항목
- 원본 `.apkg` 파일은 수정하지 않는다.

### 복습 이력 처리

MVP의 필수 조건은 **카드 내용과 덱 구조를 신뢰할 수 있게 가져오는 것**이다.

복습 이력과 due 상태를 완전하게 이전할 수 있는지는 기술 스파이크로 검증한다. 완전 이전을 지원하지 못하는 경우 가져오기 전에 명확하게 고지하고, 사용자가 동의한 경우에만 Neo-Anki에서 새 일정으로 시작한다.

### 완료 조건

- 지원 범위 안의 덱과 카드가 누락 없이 표시된다.
- 지원하지 않는 요소가 있으면 사용자가 가져오기 결과에서 확인할 수 있다.
- 가져오기 실패가 원본 Anki 파일에 영향을 주지 않는다.

## 6.5 덱별 선택 설정

### 설정 항목

- 목표일: 없음 또는 날짜 지정
- 카드 중요도: 핵심 / 일반 / 보충
- 하루 신규 카드 상한
- 오늘 학습량 수동 조정

### 설정 원칙

- 모든 항목은 덱 생성 이후에도 변경할 수 있다.
- 목표일이 없는 덱은 일반적인 장기 반복 덱으로 작동한다.
- 목표일이 있는 덱은 남은 범위를 목표일까지 분배한다.
- 사용자 전체를 시험형, 언어형 등으로 분류하지 않는다.

### 완료 조건

- 서로 다른 덱에 서로 다른 목표일과 중요도 체계를 적용할 수 있다.
- 설정을 변경하면 이후 학습 계획이 재계산된다.

## 6.6 오늘의 학습 큐

### 기본 구성

오늘의 큐는 다음 요소를 조합한다.

1. 오늘 복습할 카드
2. 목표일까지 필요한 신규 카드
3. 카드 중요도
4. 사용자가 설정한 일일 상한
5. 이전 세션에서 보류한 어려운 카드

### 초기 우선순위

1. 복습 예정 카드
2. 핵심 신규 카드
3. 일반 신규 카드
4. 보충 신규 카드

### 목표일이 있는 덱의 신규 카드 산정

초기 버전은 설명 가능한 단순 방식으로 시작한다.

```text
권장 신규 카드 수 = 남은 신규 카드 수 ÷ 남은 학습 가능 일수
```

휴일, 예상 학습 시간, 카드별 난이도 예측은 MVP에서 자동 계산하지 않는다.

### 사용자 통제

- 학습 시작 전에 신규 카드와 복습 카드 수를 보여준다.
- 사용자는 오늘 분량을 줄이거나 늘릴 수 있다.
- 특정 덱만 학습하거나 여러 덱을 합쳐 학습할 수 있다.

### 완료 조건

- 목표일과 중요도에 따라 서로 다른 덱의 오늘 학습량이 달라진다.
- 사용자가 자동 계획을 이해하고 수동으로 조정할 수 있다.

## 6.7 복습 세션

### 기능

- 질문 표시
- 답 보기
- Again / Hard / Good / Easy 평가
- 키보드 단축키
- 현재 진행 수와 남은 카드 수
- 세션 중 카드 편집
- 카드 보류
- 중간 종료 후 이어하기

### 신규 사용자 안내

첫 복습에서만 평가 기준을 짧게 보여준다.

- Again: 기억하지 못함
- Hard: 일부만 기억함
- Good: 필요한 내용을 기억함
- Easy: 바로 정확하게 기억함

필수 튜토리얼 화면은 만들지 않는다.

### 완료 조건

- 마우스와 키보드 모두로 한 세션을 끝낼 수 있다.
- 사용자가 평가 결과를 남기고 이후 복습 일정에 반영할 수 있다.

## 6.8 반복 루프 방지

MVP의 핵심 차별 기능이다.

### 초기 규칙

- 한 카드가 같은 세션에서 두 번 Again을 받으면 `어려운 카드`로 분류한다.
- 해당 카드를 현재 주 흐름에서 잠시 제외한다.
- 다른 신규 카드와 복습 카드를 계속 진행한다.
- 세션 마지막에 어려운 카드 묶음으로 다시 제시한다.
- 사용자가 오늘 다시 볼지 다음 학습으로 넘길지 선택한다.

### 설계 원칙

- 어려운 카드를 버리지 않는다.
- 한 카드가 전체 범위 학습을 막지 않는다.
- 자동 보류 이유를 짧게 설명한다.
- 사용자가 즉시 다시 보기로 되돌릴 수 있다.

### 완료 조건

- 반복 실패 카드가 있어도 사용자가 나머지 예정 카드를 계속 볼 수 있다.
- 보류한 카드가 사라지지 않고 세션 종료 시 별도로 표시된다.

## 6.9 최소 학습 현황

### 홈과 덱 상세에 표시

- 오늘 완료한 카드 수
- 오늘 남은 카드 수
- 신규 카드 수
- 복습 카드 수
- 아직 보지 않은 카드 수
- 어려운 카드 수
- 목표일까지 남은 날짜
- 핵심 카드 학습률

### 원칙

- 정교한 시험 준비도 점수보다 현재 행동에 필요한 정보만 제공한다.
- 예상 성적처럼 근거가 약한 수치를 표시하지 않는다.

### 완료 조건

- 사용자가 오늘 남은 학습과 덱의 전체 진행 상태를 구분해 이해할 수 있다.

## 6.10 로컬 저장과 데이터 보호

### 기능

- 로컬 우선 저장
- 앱 종료 및 주요 변경 시 자동 저장
- 수동 백업 파일 생성
- 삭제 전 확인
- 가져오기 실패 시 롤백
- 원본 Anki 파일 보존

### 완료 조건

- 앱을 재실행해도 덱, 카드, 설정, 복습 기록이 유지된다.
- 실패한 가져오기가 기존 데이터에 영향을 주지 않는다.

# 7. Should: 공개 베타 전 우선 검토

다음 기능은 핵심 흐름을 막지는 않지만 제품 신뢰와 실사용성을 높인다.

## Anki 호환성 강화

- 기존 복습 이력과 due 상태 이전
- 지원 범위 안의 덱을 `.apkg`로 다시 내보내기
- 더 많은 기본 노트 타입 지원
- 가져오기 전 미리보기와 선택 가져오기

## 카드 작성 경험 개선

- Basic and Reversed 네이티브 생성
- 카드 일괄 선택과 편집
- CSV Import/Export
- 수식 입력과 렌더링
- 이미지 크기 자동 조정

## 계획과 현황 개선

- 예상 완료일
- 목표일 변경 시 변화 요약
- 덱별 학습 일시 중지
- 최소 학습 히트맵
- 취약 챕터를 수동 분류할 수 있는 기능

## 사용성 개선

- 검색과 필터
- 실행 취소
- 접근성 기본 지원
- 단축키 사용자 설정
- 다크 모드

# 8. Later: 핵심 루프 검증 후 업데이트

# 12. 성공 지표

MVP 테스트에서는 기능 사용량보다 가설과 직접 연결된 지표를 본다.

## 진입

- 신규 사용자가 설명 없이 첫 덱을 생성할 수 있는가
- 기존 사용자가 첫 시도에 Anki 덱을 가져올 수 있는가
- 앱 실행부터 첫 학습 시작까지 걸린 시간

## 학습

- 계획된 카드 중 실제 완료한 비율
- 한 세션에서 서로 다른 카드를 본 비율
- 반복 실패 카드 때문에 학습을 중단한 세션 비율
- 어려운 카드 보류 후 나머지 범위를 완료한 비율

## 목표 기반 계획

- 목표일이 있는 덱의 일일 계획 수락률
- 자동 계획을 사용자가 수정한 비율과 수정 방향
- 핵심 카드가 일반·보충 카드보다 먼저 학습되었는가

## 만족도

- 오늘 무엇을 해야 하는지 이해하기 쉬웠는가
- 어려운 카드가 전체 진도를 막는 느낌이 줄었는가
- 기존 Anki보다 시험 준비 흐름이 명확해졌는가

# 13. 기술 스파이크

본 구현 전에 다음 항목을 작은 실험으로 검증한다.

1. `.apkg` 구조와 덱·노트·카드·미디어 파싱
2. Basic, Reversed, Cloze 렌더링
3. 기존 복습 이력과 due 상태 이전 가능 범위
4. 지원하지 않는 템플릿 탐지와 결과 보고
5. 검증된 SRS 또는 FSRS 구현 재사용 방식
6. 반복 루프 방지 큐를 기존 스케줄과 분리하는 방식
7. 로컬 데이터베이스와 원본 Anki 데이터 분리
8. 지원 범위 안의 `.apkg` 재내보내기 가능성

# 14. MVP 완료 정의

다음 조건을 모두 만족하면 MVP v0.1을 완료한 것으로 본다.

- 신규 사용자가 온보딩 없이 덱을 만들고 기본 카드를 학습할 수 있다.
- 기존 사용자가 지원 범위 안의 Anki 덱을 가져와 학습할 수 있다.
- 여러 덱이 각각 다른 목표일과 카드 중요도를 가질 수 있다.
- 시스템이 덱별 목표를 반영해 오늘의 학습 큐를 구성한다.
- 사용자가 계획된 분량을 확인하고 조정할 수 있다.
- Again / Hard / Good / Easy로 복습 기록을 남길 수 있다.
- 반복 실패 카드가 나머지 학습 진행을 막지 않는다.
- 오늘의 학습과 덱 전체 진행 상태를 확인할 수 있다.
- 모든 데이터가 로컬에 안전하게 저장되고 다시 열 수 있다.
- 지원하지 않는 Anki 요소가 조용히 손실되지 않는다.

## 최종 경계 문장

> Neo-Anki MVP는 완성형 Anki 대체품이 아니다. 기본 카드 학습 위에 덱별 목표, 우선순위, 오늘의 학습 계획, 반복 루프 방지를 얹어 핵심 학습 가치를 검증하는 첫 제품이다.
