## IME 일괄 점검

**흉내 방법**: 입력 칸에 앞부분을 확정 입력(`Input.insertText`)하고 마지막 글자를 `Input.imeSetComposition`으로 조합 중에 둔 뒤 Enter를 보냈다. 이때 `keydown`은 `key="Enter"` · `keyCode 13` · **`isComposing=true`**로 왔다(캡처 단계에서 기록). 그 뒤 실제 IME가 하는 조합 확정을 `insertText`로 흉내 냈다(**Enter 1번 모델**). 확정 뒤 `isComposing=false`인 Enter가 한 번 더 오는 경우는 Enter를 한 번 더 보내 흉내 냈다(**Enter 2번 모델**).

**한계**: CDP 조합은 실제 Windows 한글 IME와 다를 수 있다. 실제로 첫 `keydown`이 `key="Enter"`로 오는지(`"Process"`/229일 수도 있다), 확정 뒤 Enter가 한 번 더 오는지는 CDP로 알 수 없다. 그래서 아래 판정은 모두 **"흉내에서 재현 · 실제 IME는 사람 확인 필요"**다. 다만 같은 방법에서 대조군(조합 중 Enter를 무시하는 핸들러)은 정상, 의심 핸들러만 틀어져 흉내가 두 종류를 구분한다는 것은 확인했다.
