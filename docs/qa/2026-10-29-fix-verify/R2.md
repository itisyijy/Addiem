# R2 · 실계정 다시 확인 (Google Drive · ChatGPT)

- 날짜: 2026-10-29 12:00–
- 대상: 0.1.1 배포 빌드 `bce50c7`, 실제 Google 키 포함(`%TEMP%\na-fx-rel\run\addiem.exe`, 설치본과 같은 빌드)
- 목적: R(0.1.0)에서 실제 Drive로 재현한 문제와 P0 동기화 수정이 실제 Drive에서도 고쳐졌는지 본다.
- 로그인은 사용자가 기본 브라우저에서 직접 했다(테스트 Google 계정). 코디네이터는 암호 · 이메일을 입력하지 않았다. 이메일은 기록에서 `<email>`로 가렸고 캡처는 남기지 않았다.
- 실제 앱 데이터 · 키체인 항목은 건드리지 않았다(검증용 `ADDIEM_DATA_DIR`마다 `…@<해시>` 항목).

- 설치 전: 설치된 0.1.0(`%LOCALAPPDATA%\Addiem`, 제거 항목 "Addiem 0.1.0"), 실제 데이터 파일 819개의 크기 · 수정 시각을 적었다(내용은 열지 않음).
- `Addiem_0.1.1_x64-setup.exe /S` (해시 확인 뒤) 22초, 종료 코드 0. `/R`을 주지 않아 설치 뒤 앱이 뜨지 않았다(실제 데이터를 열지 않음).
- 설치 뒤: 제거 항목 "Addiem 0.1.1", 같은 폴더, `llm` · `tts` 함께, 시작 메뉴 바로 가기 1개. 설치된 exe는 확인에 쓴 키 든 빌드와 3바이트만 다르다(설치본 종류 표시 `NSS` · `UNK`).
- 설치된 0.1.1을 임시 데이터 폴더로 띄우면 0.8초에 홈이 뜨고, 버전 0.1.1, Google 연결 설정됨(키 포함), 끄면 잘 닫힌다.
- 실제 데이터: 설치 전과 같고, 10-28 기준 목록과도 같다(819개, 바뀜 · 없어짐 · 새로 생김 0).

## 결론

R(0.1.0)에서 재현한 Drive · ChatGPT 문제(R-01 · R-02 · R-04 · R-05 · R-06 · R-08 · R-09)와 동기화 P0 세 가지(P0-1 두 경우 · P0-2 · P0-3)가 실제 계정에서 모두 고쳐졌다. 새로 찾은 문제는 없다(R2-01은 참고).

## 하네스 메모

- 스크립트의 창 글자 읽기(`lib.mjs` `modal`)가 셸 이스케이프 탓에 공백 대신 영문 `s`를 지워 "re tore" · "Plu  · Pro"처럼 찍혔다. 앱 글자는 맞다.
- 화면에 Drive 상태 팝오버가 열린 채 상단 [설정]을 누르면 설정으로 가지 않았다. 팝오버의 [설정 열기]로 갔다.

- 처음 B에서 복사본 수정을 찾을 때 "앞면 앞 12자" 검색이 같은 노트의 다른 카드(뒷면 카드)를 먼저 돌려줘 FAIL로 찍혔다. "복사본 수정"으로 다시 찾으니 B에 있었다. 앱 문제가 아니다.
- 화면 복구에서 맞는 암호를 넣은 뒤 미리보기가 뜨기까지 6초가 넘게 걸렸다(Drive에서 백업을 받고 Argon2로 연다). 스크립트가 6초만 기다려 한 번 놓쳤다.
- 홈에 Drive 상태 팝오버가 열려 있으면 상단 [설정] 클릭이 팝오버만 닫는다(팝오버의 [설정 열기]로 갔다). 사용자도 같은 동작을 보지만 팝오버 바깥 클릭으로 닫히는 것이라 문제로 세지 않았다.
