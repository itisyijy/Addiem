# Anki 장기 사용자 인터뷰

## 문서 목적

이 문서는 Addiem 기획을 위해 수행한 장기 Anki 사용자 인터뷰를 정리한 사용자 리서치 문서다.

인터뷰 대상자는 고등학교 1학년부터 Anki를 사용했으며, 수능 영단어, 대학 전공시험, 정보처리기사 등 시험 중심의 암기 과업에 Anki를 활용해 왔다.

## 사용자 요약

### 사용자 유형

명확한 시험 목표와 마감일이 있을 때 Anki를 집중적으로 사용하는 장기 사용자

### 핵심 학습관

- 암기 자체를 선호하지 않지만, 피할 수 없는 암기를 효율적으로 처리하기 위해 Anki를 사용한다.
- 이해되지 않은 내용을 Anki로 억지로 외우지 않는다.
- 먼저 개념을 이해한 뒤, Anki를 기억 정착 도구로 활용한다.
- 원문을 그대로 복사하듯 외우는 것보다 핵심 키워드에서 출발해 자신의 문장으로 설명하는 것을 중요하게 본다.
- Anki는 꾸준함 자체보다 성적, 자격증 취득 등 실질적인 목표 달성을 위한 수단에 가깝다.

## 사용 목적과 맥락

### 고등학교

처음에는 수능 영어 단어 암기를 위해 Anki를 사용했다.

- 영단어장 책에서 단어와 뜻을 직접 앞뒷면 카드로 만들었다.
- 아침 자습시간과 자투리 시간에 복습했다.
- 쉽게 기억한 단어는 복습 주기가 길어지고, 어려운 단어는 반복 노출되는 방식이 종이 카드보다 효과적이라고 느꼈다.

### 대학교

대학 입학 이후에는 Anki 활용 범위를 전공시험과 자격증으로 확장했다.

- 전공 개념 설명
- 특성 서술
- 주관식 답변 준비
- 정보처리기사 필기와 실기 대비

대학 시험은 개념 이해만으로 끝나지 않고, 결국 내용을 시험장에서 꺼내어 서술해야 하기 때문에 통암기가 중요하다고 느꼈다.

### 비시험 학습

일반적인 개발 공부나 자기계발에는 Notion을 주로 사용한다.

명확한 시험, 자격증, 평가, 데드라인이 없는 학습에는 굳이 Anki를 사용하지 않는다.

## 현재 학습 흐름

### 1. 목표 설정

시험이나 자격증과 같은 목표가 생기면 Anki 사용을 시작한다.

### 2. 자료 수집

대학 시험에서는 다음 자료를 활용한다.

- 교수자가 제공한 강의용 PPT 또는 PDF
- GoodNotes 필기를 OCR 처리한 PDF
- 강의계획서
- 교수자 강조 표시
- 기출문제
- 기타 보조자료

자격증 시험에서는 다음 자료를 활용한다.

- 교재
- 공유 학습자료
- 요약자료
- 기출문제
- 암기할 가치가 있는 용어와 개념

### 3. 내용 이해

AI가 카드를 만들어주더라도 먼저 강의자료를 정독하고 내용을 이해한다.

카드 생성 과정 자체가 학습의 일부라는 점에는 동의하지만, 현실적인 시간 부족 때문에 카드 생성은 AI에 맡기는 편이다.

### 4. 카드 생성과 Import

과거에는 직접 슬라이드를 보며 자신의 언어로 카드를 작성했다.

현재는 ChatGPT나 Claude 같은 LLM으로 대량의 카드를 생성한 뒤 Anki에 Import한다.

시험 범위가 수백 페이지이고 카드 수도 많기 때문에 모든 카드를 사전 검수한 뒤 학습을 시작하는 것은 사실상 불가능하다.

### 5. 복습 중 검수

카드를 먼저 Import하고, 복습 과정에서 문제가 발견되면 수정하거나 삭제한다.

다음과 같은 문제가 자주 발생한다.

- 답변이 지나치게 긴 카드
- 중요하지 않은 내용을 묻는 카드
- 질문과 답변이 명확하게 대응하지 않는 카드
- 개행과 넘버링이 없는 카드
- 정답 구조가 일관되지 않은 카드
- 핵심보다 부연 설명이 더 눈에 띄는 카드
- 사용자의 언어와 맞지 않는 장황한 문장
- 하나의 카드에 너무 많은 내용을 요구하는 카드

### 6. 시험 직전 전체 복습

시험 직전에는 불안감 때문에 전체 범위를 다시 훑는 것을 선호한다.

기본 복습을 모두 처리한 뒤 Custom Study를 사용하기도 하지만, 이미 숙달한 카드까지 모두 다시 보게 되어 시간 효율이 낮다고 느낀다.

### 7. 시험 종료 후 보관

시험이나 자격증 취득 후에는 일반적으로 해당 덱을 다시 학습하지 않는다.

기말고사 범위에 중간고사 내용이 포함되면 기존 덱을 재사용한다. 현재는 이전 덱을 AnkiWeb에 보관하는 편이다.

## 카드 생성 경험

### 직접 제작할 때의 특징

- 슬라이드의 문장을 그대로 복사하지 않는다.
- 자신의 말로 한 번 정제해 작성한다.
- 핵심 내용 선별보다 타이핑과 재작성 과정이 더 번거롭다.
- 이미지 일부 가리기, 빈칸 만들기, 문제 형태로 가공하기가 어렵다.
- 힌트를 과도하게 주지 않으면서 핵심을 묻는 질문 설계가 어렵다.

### 좋은 카드의 기준

- 하나의 질문에 하나의 내용이 대응한다.
- 질문과 답변의 연결이 명확하다.
- 답변이 지나치게 길지 않다.
- 핵심을 빠르게 파악할 수 있다.
- 사용자가 자신의 언어로 재구성해 설명할 수 있다.

### 나쁜 카드의 기준

- 질문은 단순하지만 답변이 지나치게 길다.
- 여러 항목과 설명을 한 카드에서 모두 요구한다.
- 표현이 장황하고 구조가 복잡하다.
- 핵심 내용보다 부연 설명이 더 눈에 띈다.
- 사용자의 언어와 맞지 않아 암기 부담이 커진다.

## 시험 유형별 차이

객관식과 서술형은 본질적으로 같은 암기 문제를 다루지만, 요구되는 답변 수준이 다르다.

### 객관식

- 보기 중 정답을 선택할 수 있다.
- 비교적 많은 힌트가 제공된다.
- 키워드 중심의 기억도 도움이 된다.

### 서술형

- 보기 없이 내용을 떠올려야 한다.
- 핵심 키워드뿐 아니라 관계와 설명도 필요하다.
- 자신의 문장으로 답변을 구성해야 한다.
- 더 적은 힌트와 더 높은 답변 품질을 요구한다.

## 복습 경험

### 가장 큰 스트레스

- 카드가 많지만 주어진 시간이 부족할 때
- 수백 장의 긴 서술형 카드를 직접 채점해야 할 때
- 특정 어려운 카드가 반복되어 신규 진도가 막힐 때
- 저품질 카드와 순수한 암기 실패를 구분하기 어려울 때

### 서술형 자기 채점 방식

사용자는 다음 기준으로 자신의 답변을 평가한다.

- 핵심 키워드를 기억했는가
- 키워드 간 관계를 설명할 수 있는가
- 자신의 문장으로 서술할 수 있는가
- 카드 뒷면과 의미상 일맥상통하는가

원문과 문장 단위로 완전히 일치할 필요는 없지만, 키워드만 나열하는 것도 충분하지 않다고 본다.

### Again, Hard, Good, Easy 기준

- Again: 거의 또는 전혀 기억하지 못함
- Hard: 일부 항목이나 세부 내용이 부족함
- Good: 필요한 내용을 기억해냄
- Easy: 보자마자 전체 내용이 쉽게 떠오름

네 단계는 충분히 명확하며, 더 세밀한 수치 평가는 오히려 선택 부담을 높일 수 있다고 본다.

## 계속 틀리는 카드

계속 틀리는 카드는 대부분 이해 부족이 아니라 암기 실패다.

보통 Again을 반복하다가 계속 기억하지 못하면 해당 카드를 건너뛰고 나중에 다시 학습한다.

대표적인 어려움은 다음 두 가지다.

### 헷갈림

속성과 예시처럼 서로 매칭해야 하는 항목이 엇갈리는 경우다.

이 경우에는 반복과 원자료 기반 확인이 도움이 된다.

### 머리에 들어오지 않음

하나의 카드에 내용이 너무 많거나 문장이 복잡한 경우다.

이 경우에는 반복보다 카드 재구성이 더 적절하다고 본다.

가능한 재구성 방식은 다음과 같다.

- 답변 분할
- 질문 분해
- 부담 축소
- 힌트 제공
- 원자료 기반 해설 제공
- 그림, 영상, 외부 설명자료 연결

## 스케줄링 요구

Anki의 기본 SRS에는 만족한다.

다만 시험 중심 사용자에게는 다음 요소가 추가로 필요하다고 본다.

- 시험일까지 남은 기간
- 카드 중요도
- 아직 보지 않은 범위
- 핵심 카드 우선 학습
- 일정 변경에 따른 자동 재계산
- 어려운 카드와 신규 카드의 균형

사용자는 1순위 핵심 카드를 먼저 회독한 뒤, 2순위 세부 내용과 고득점 요소로 넘어가는 흐름을 선호한다.

## 학습 세션 종료

가장 이상적인 종료 시점은 예정된 모든 카드를 완료했을 때다.

그러나 현실적으로 다음 상황에서는 잠시 쉬는 것이 좋다고 본다.

- 핵심 범위를 한 번 돌았을 때
- 집중력이 크게 떨어졌을 때
- 피로가 누적되었을 때

학습량 자체보다 뇌의 피로를 최소화하면서 효율을 극대화하는 것이 중요하다.

## 덱 운영

### 구조

덱은 보통 다음과 같이 계층적으로 관리한다.

과목 또는 자격증 → 시험 또는 학습 단위 → 챕터

하위 덱을 파일 시스템의 디렉터리처럼 사용한다.

태그는 활용 방법을 잘 몰라 거의 사용하지 않는다.

### 밀린 복습

복습이 밀리면 가능한 한 모두 처리하려고 한다.

시간이 부족하면 일부만 먼저 보고, 남은 분량을 차차 처리한다.

초기화나 덱 포기는 선호하지 않는다.

## 동기화와 파일 관리

- AnkiWeb의 자동 동기화를 매우 긍정적으로 평가한다.
- iOS 앱이 유료여서 모바일 웹을 사용했다.
- 이미지가 텍스트보다 지나치게 크게 보이는 문제를 경험했다.
- 대량 Import 시 CSV보다 JSON 같은 구조화 포맷이 더 적절할 수 있다고 생각한다.
- 개인 드라이브나 GitHub 같은 선택적 동기화와 백업 옵션에도 관심이 있다.

## 학습 통계

단순 공부 시간이나 연속 학습일보다 다음 정보가 더 유용하다고 본다.

- 시험 준비도
- 핵심 범위 숙달률
- 취약 개념
- 아직 보지 않은 범위
- 계속 틀리는 카드
- 예상 완료일
- 시험까지 남은 날짜
- 일별 학습 히트맵

공유 덱을 사용하는 경우 다른 학습자와 진도나 숙달도를 비교하는 기능도 동기부여에 도움이 될 수 있다고 본다.

## 공유와 협업

공동 덱 편집 자체는 유용하지만, 참여자가 늘어날수록 품질과 신뢰 문제가 발생할 수 있다.

선호하는 방식은 GitHub PR과 유사하다.

- 개인이 수정한 카드를 원본 덱에 제안한다.
- 관리자가 변경 내용을 검토한다.
- 승인된 변경만 원본 덱에 반영한다.
- 개인 수정본과 원본을 분리해 유지한다.
- 변경 이력과 버전을 관리한다.

다만 협업 기능 때문에 UI와 UX가 과도하게 복잡해지는 것은 경계한다.

## 자동화와 사용자 통제

다음 자동화에는 긍정적이다.

- 카드 우선순위 변경
- 긴 카드 분해
- 학습 순서 조정
- 일정 재계산
- 저품질 카드 개선

그러나 완전 자동 적용보다는 다음 흐름을 선호한다.

1. 변경 사항 제안
2. 변경 이유 설명
3. 사용자 승인
4. 변경 내역 저장
5. 언제든 이전 상태로 복구

## 핵심 인터뷰 인사이트

1. 사용자는 Anki의 SRS보다 시험일까지의 완주 전략에서 더 큰 문제를 느낀다.
2. 어려운 카드가 항상 기억력 문제인 것은 아니며, 카드 품질 문제일 수 있다.
3. 긴 서술형 카드의 자기 채점은 높은 인지 부하를 만든다.
4. 핵심 카드와 세부 카드를 동일하게 다루면 시험 직전 효율이 떨어진다.
5. 자동화는 필요하지만 사용자 통제, 이유 설명, 되돌리기가 필수다.
6. Addiem은 새로운 암기 알고리즘보다 목표, 품질, 우선순위, 진도 관리에서 차별화될 가능성이 크다.
