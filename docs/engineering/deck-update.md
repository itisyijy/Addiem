# 덱 업데이트 가져오기 (8.7 공유 · 협업의 서버 없는 조각)

2026-10-18. 설계 메모. **엔진 1단계 · 화면 2단계 구현됨 (2026-10-18, 브랜치 `feat/deck-update`, 9장 · 10장).** 결정 후보는 [DECISIONS DU 섹션](../DECISIONS-PENDING-REVIEW.md). 사용자 요청: "원본 · 내 수정 · 새 버전을 비교해 내 수정과 복습 기록을 보존하는 기준부터 정해 주세요."

## 0. 문제와 원칙

- **상황.** 다른 사람이 만든 공유 덱 v1(.apkg)을 가져와 공부하고 몇 장 고쳤다. 만든 사람이 고친 v2 를 다시 받는다.
- **지금.** 같은 guid 노트는 건너뛴다 (I5, `import.rs` `run_import_selected` 노트 단계의 `exists → dup`). 만든 사람의 수정 · 새 필드 · 새 카드 종류는 들어오지 않고 새 노트만 들어온다. 내가 지운 노트는 새 노트로 다시 들어온다.
- **원하는 것.** 바뀐 노트만 갱신한다. 내가 고친 필드, 내 복습 기록 · 일정은 지킨다.

원칙: ① 업데이트는 복습 기록 · 일정을 건드리지 않는다 (SRS-preserving). ② 알리지 않고 내 내용을 바꾸지 않는다 (mvp-scope 9장 Out "원본 데이터를 알리지 않고 자동 수정"): 적용 전에 수를 다 보이고, 충돌은 내 것이 기본이다. ③ 되돌릴 수 있다 (적용 전 자동 백업). ④ 인터뷰의 "개인 수정본과 원본을 분리해 유지"를 서버 없이 한다: git 의 merge-base 처럼 **마지막으로 받은 원본**을 기억하고 원본(B) · 내 것(M) · 새 버전(N)을 3-way 로 비교한다. ⑤ 협업 기능으로 UI 가 복잡해지는 것을 경계한다 (인터뷰 · product-direction): 1단계는 노트마다 고르기만 한다.

비교: Anki 의 .apkg "노트 업데이트: 더 새것이면"은 수정 시각만 본다. 만든 사람이 나중에 고쳤으면 내 수정이 노트째 덮인다. 공유 덱 애드온의 "보호할 필드"는 지킬 필드를 사용자가 미리 정해야 한다. 3-way 는 미리 정할 것 없이 실제로 고친 필드만 지킨다.

## 1. 원본(B)을 무엇으로 삼나

**지금 DB 에는 원본이 남지 않는다.**

| 있는 것 | 원본으로 쓸 수 있나 |
|---|---|
| `note.anki_guid` · `anki_note_id` | 같은 노트를 알아보는 데만 쓴다 |
| `note.created_at` (= Anki 노트 id, ms) · `updated_at` (가져올 때 Anki mod × 1000) | `save_note_fields` 가 저장할 때마다 now 로 쓰고(값이 같아도), 동기화로 다른 기기 값이 된다. 내용은 없다 |
| `note.fields` | 미디어 이름 바꾸기(I85) · 자리 맞추기(Q2-13)를 거친 값이고, 고치면 덮인다 |
| `note_type.anki_raw` | 가져오기가 채우지 않는다 (늘 NULL) |
| `import_batch` | 기기 안 표, 동기화하지 않는다 |

| 후보 | 다른 기기 | 크기 | 필드 단위 판정 | 원본 글 보기 | 판단 |
|---|---|---|---|---|---|
| **(a) 필드 해시를 노트 열에** | 동기화 열로 따라간다 | 노트당 수십 바이트 | 된다 | 안 된다 | **추천** |
| (b) 필드 값 사본을 노트 열에 | 따라간다 | 노트 글만큼 한 벌 더 (Drive 스냅샷도) | 된다 | 된다 | 2단계 "원본 보기" 때 (a) 의 같은 열을 사본으로 바꾼다 |
| (c) Anki 노트 mod 만 | 따라간다 | 8바이트 | 안 된다 (노트 단위, 내가 고쳤는지 모른다) | 안 된다 | 그림 내용만 바뀌면 mod 가 그대로라 보조로도 쓰지 않는다 |
| (d) 가져온 .apkg 보관 | 기기 안 (올리면 수백 MB, K3 · K6 원칙과 어긋난다) | 덱 크기 | 된다 | 된다 | 고르지 않는다 |
| (e) 새 표 `note_origin` | SYNC_TABLES · 자연 키 · 지우기 규칙(K29)을 새로 맞춰야 한다 | (a) 와 같다 | 된다 | — | 열이 더 싸다 |

**추천 (a).**

- `note.origin` (TEXT, NULL 허용) = `{"f": [자리마다 해시], "t": "태그"}`. 해시는 **넣은 값**(자리 맞추기 · 미디어 이름 바꾸기 뒤)을 가볍게 정규화한 글의 SHA-256 앞 16자다. 정규화는 공백 · 줄바꿈 접기, `<br/>` · `<br />` → `<br>`, 끝의 `<br>` · 공백 떼기, `&nbsp;` → 공백이다 (편집기가 바꾼 모양을 내 수정으로 보지 않게. ponytail: 모양만 다른 HTML 을 다 거르지는 못한다). 태그는 글자 그대로 둔다 (짧고, 집합 3-way 에 원본 집합이 필요하다). 출처 태그는 뺀다.
- `note_type.origin` (TEXT, NULL 허용) = `{"f": [[Anki 필드 이름, 우리 자리 | null]…], "t": [{"o": Anki ord, "n": 이름, "our": 우리 ord | null, "q": 앞면 해시, "a": 뒷면 해시}], "c": CSS 해시}`. Anki ord → 우리 ord 를 적어 두므로 다음 업데이트는 이름 · 앞면 어림(`incoming_ords`)없이 카드 종류를 찾는다. (구현에서 바꿈, DU21: `f` 는 Anki 순서의 (이름, 우리 자리) 쌍이다. 새 필드가 끝 자리에 붙으면 Anki 순서와 자리가 달라진다. null = 이 앱에서 지웠거나 넣지 못한 것. 템플릿 해시는 Anki 필드 이름 그대로, CSS 해시는 쉬운 편집 줄 상자 CSS 를 뺀 값.)
- **쓰는 때.** 처음 가져올 때(새 노트 · 새 유형, 미디어 이름 바꾸기가 끝난 뒤)와 업데이트를 적용할 때다. 적용할 때는 고른 결과와 상관없이 **새 버전 값**으로 쓴다. 그래서 내 것을 지킨 필드는 다음 업데이트에서도 "내가 고침"으로 남는다. "새 노트만 더하기"로 건너뛴 노트는 건드리지 않는다.
- **동기화.** 두 열 모두 동기화 대상 표(`note`, `note_type`)의 NULL 허용 열이라 raw_cols 로 따라가고, 옛 앱은 건너뛴다 (I78 · I82 와 같다). 기기 전용으로 두면 다른 기기에는 기준이 없어 바뀐 노트가 모두 "기준 없음"이 된다. 다른 기기에서 업데이트를 받으면 필드 · 태그 · origin · 새 노트 · 카드 · 유형 변경이 보통 편집처럼 들어와 같은 상태가 된다. 그 기기에서 다음 버전을 가져와도 같은 기준으로 판정한다. 같은 파일을 다시 가져오면 바뀌는 것이 없다 (멱등).
- 열 단위 LWW 라 `origin` 과 `fields` 가 다른 기기 것일 수 있다 (A 가 업데이트하는 동안 B 가 고침 → fields = B, origin = v2). 그러면 다음 판정에서 B 의 값이 "내가 고침"으로 지켜진다. 어긋나도 지키는 쪽으로만 어긋난다.
- **내가 지운 노트.** 기기 안 표 `origin_gone(guid, at)` 와 `note` 삭제 트리거(`WHEN OLD.origin IS NOT NULL`)로 남긴다. 지우는 길(카드 삭제 · 덱 삭제 · 카드 종류 삭제 · 빈칸 지우기 · 동기화로 받은 삭제)이 여럿이라 트리거 하나로 모은다. 받은 삭제에도 트리거가 돌아 기기마다 쌓이므로 동기화 표로 둘 필요가 없다. 한계: 지운 뒤에 스냅샷으로 합류한 기기는 모른다.

## 2. 노트 판정

1. **같은 노트**: guid 로 찾는다. 들어온 노트의 모델 id 가 우리 노트의 유형과 다르면(만든 사람이 노트 유형을 바꿨다) 고치지 않고 알린다.
2. **들어온 값 맞추기(N)**: 지금 가져오기와 같은 변환을 한다. 필드 자리는 기준이 있으면 기준 Anki 필드 이름으로 찾고, 없으면 `incoming_slots`(Q2-13)를 쓴다. 미디어 이름은 I85, 출처 태그는 뺀다.
3. **자리마다 비교** (해시):

| B · M · N | 자리 결과 |
|---|---|
| B = M = N | 그대로 |
| B = M ≠ N | **새 버전** (만든 사람만 고침) |
| B ≠ M = N | 그대로 (둘이 같게 고침, 기준만 새로) |
| B = N ≠ M | **내 것** (나만 고침) |
| B ≠ M ≠ N, M ≠ N | **충돌** |
| 기준 없음 (예전에 가져온 노트), M = N | 그대로 (기준을 채운다) |
| 기준 없음, M ≠ N | 가져온 뒤 고친 흔적이 없으면 새 버전, 있으면 충돌 (DU18) |

내가 나중에 더한 필드는 기준 해시가 없어 빈 값으로 보고 비교한다 (보통 "내 것"이 된다).

4. **노트 결과**:

| 노트 | 조건 | 처리 |
|---|---|---|
| 바뀐 노트 | 새 버전 자리만 있다 | 자동 적용 |
| 합친 노트 | 새 버전 자리와 내 것 자리가 있고 충돌은 없다 | 묻지 않고 합친다 (DU5, 사용자 결정 2026-10-18). 요약에 "합친 노트 n개" |
| 충돌 노트 | 충돌 자리가 하나 이상 있다 | 검토: [내 것 유지](기본) / [새 버전으로], [모두 내 것] / [모두 새 버전]. **어느 선택이든 충돌한 자리에만 적용하고, 같은 노트의 충돌 없는 변경은 위 표대로 합친다** (DU6, 사용자 결정 2026-10-18) |
| 내 수정 지킴 | 내 것 자리만 있다 | 그대로 둔다 (요약에 수) |
| 그대로 | — | 기준만 새로 쓴다 |

**필드 단위 vs 노트 단위.** 비교는 필드, 고르기는 노트(1단계)로 한다. 필드로 비교하면 "내가 추가 설명에 덧붙이고 만든 사람은 앞면 오타를 고친" 흔한 경우를 묻지 않고 합칠 수 있다. 노트로만 비교하면 이것도 충돌이다. 필드별 고르기 화면은 2단계다.

5. **태그 · 기출 · 출처.** 태그는 집합 3-way 다: 결과 = (M − (B − N)) ∪ (N − B). 지금은 앱에 태그 편집이 없어 M = B 이므로 결과는 N 이다. 출처 태그(`Neo-Anki::출처::`)는 N 에서 먼저 뺀다 (지금 가져오기와 같다, T2-02). 기출 표시(`exam_hits` · `exam_names`)는 지금 값이 지금 태그의 해석(N9)과 같으면 고치지 않은 것으로 보고 새 태그로 다시 채운다. 다르면 사용자가 고친 표시라 지킨다. 중요도 태그 제안은 지금처럼 새로 넣은 카드만 세고, 사용자가 정한 덱은 건드리지 않는다 (I1 · I24).

6. **노트 유형** (`note_type.origin` 과 비교):

| 바뀐 것 | 결과 |
|---|---|
| 새 필드 (기준에 없는 Anki 필드 이름) | 우리 유형 끝 자리에 더하고 값도 넣는다 (NT19 · `field_ids` 로 동기화 안전, K39). 보이는 순서는 새 버전 순서로 하고, 내가 순서를 바꿨으면 끝에 둔다 |
| 필드 이름 바뀜 (기준 같은 위치의 이름이 N 에 없다) | 우리 이름이 기준 이름이면 새 이름으로 바꾼다 (템플릿 참조도, `rename_refs`). 내가 바꾼 이름이면 지킨다 |
| 필드 없어짐 | 남긴다. 들어온 값이 없을 뿐 비운 것이 아니라 내 값을 그대로 둔다 |
| 내가 지운(숨긴) 필드 | 값을 숨긴 자리에 넣는다 (NT10 · Q2-13 그대로) |
| 새 카드 종류 (기준에 없는 Anki 템플릿) | 더한다 (`next_ord` · 기기 몫, K39). 앞면이 비지 않는 노트에 카드를 만든다 (NT22, 덱 · 중요도는 노트의 첫 카드, C3-r) |
| 내가 지운 카드 종류 (기준에 있고 우리에 없다) | 넣지 않는다 (Q2-08 그대로) |
| 카드 종류 없어짐 (기준 · 우리에 있고 N 에 없다) | 남긴다. 카드 · 기록 · 일정 그대로 두고 알리기만 한다 |
| 카드 종류 앞 · 뒷면, CSS | 템플릿마다 B · M · N 3-way. 충돌(나도 고쳤다: 쉬운 편집으로 한 번 저장해 줄 상자가 생긴 것 포함, NT41)이면 내 모양을 지킨다 (DU9, 사용자 결정 2026-10-18). 요약에 "내 모양을 지킨 노트 유형 n개"와 [새 모양 보기] · [새 모양으로]. 새 템플릿이 쓰는 필드 이름은 우리 이름으로 고쳐 넣는다 |
| 기준 없음 (예전에 가져온 유형) | 지금처럼 덮지 않는다 (NT29). 새 필드 · 새 카드 종류는 지운 것과 구별하지 못해 Q2-08 · Q2-13 대로 알리기만 한다 |

7. **미디어.** I85 그대로 한다. 같은 이름 · 같은 내용이면 그 파일을 쓰고, 같은 이름 · 다른 내용이면 `이름-<sha8>` 로 새로 저장하고 들어온 값(N)의 참조를 고친다. 그래서 만든 사람이 그림만 바꾼 노트도 그 필드가 "새 버전"으로 잡힌다. 내 것을 지킨 노트는 옛 파일을 계속 본다. 옛 파일은 지우지 않는다 (다른 노트 · 다른 덱이 쓸 수 있다). 사전 검사는 이름이 겹치는 파일만 내용을 비교한다 (신형 패키지는 미디어 목록의 sha1, 구형은 풀어서).

## 3. 새로 생긴 노트 · 사라진 노트

| 경우 | 처리 |
|---|---|
| 새 버전의 새 노트 (처음 보는 guid) | 지금처럼 넣는다. 새 카드는 신규로 시작한다. 덱은 5장 |
| 내가 지운 노트 (`origin_gone` 에 guid) | 다시 넣지 않는다. 요약에 "내가 지운 노트 n개는 다시 넣지 않아요" |
| 새 버전에 없는 노트 | **그대로 남긴다** (DU11, 사용자 결정 2026-10-18). 카드 · 기록 · 일정 그대로 학습에 나온다. 요약 · 결과에 수와 [카드 목록에서 보기] (C2 cardIds 거르기, I55). 지우기는 사용자가 카드 목록에서 한다 (기록은 A4 로 남는다). 범위는 `origin` 이 있고, 이번 패키지 덱에 대응하는 우리 덱(`anki_deck_id`) 안에 카드가 있는 노트다. 덱을 골라 가져오면(B2-s) 고른 덱 안만 본다 |

## 4. 카드 · 복습 기록 · 일정

- 이미 있는 카드의 FSRS 상태 · 기한 · 학습 중지 · 접어두기 · 개별 중요도는 쓰지 않는다. `review_log` 는 append-only 그대로다.
- 새 .apkg 의 복습 기록은 업데이트에서 **기본 꺼짐**이다. 만든 사람의 기록이지 내 기록이 아니다. [복습 기록도 옮기기]는 남긴다: 내 덱을 Anki 에서 공부하고 다시 가져오는 경우다 (I79 중복 막기 그대로, 이미 있는 카드의 일정은 그래도 덮지 않는다).
- 카드 종류가 늘면 새 카드(신규)를 만든다. 줄면 카드를 지우지 않는다.
- **빈칸.** 카드는 (노트, 빈칸 번호)다 (NT21 ord 는 정체성, Anki 와 같다). 기록 · 일정은 **번호를 따라간다** (DU13, 사용자 결정 2026-10-18 + 보충). **새로 생긴 번호는 신규 카드로 시작한다. 없어진 번호의 카드와 복습 기록은 지우지 않고 보존한다**: 앞면 빔(NT49)으로 학습에서 빠지고, 번호가 돌아오면 다시 나온다. 번호가 바뀌면(c2 → c3) 새 c2 내용에 옛 c2 기록이 붙는다. 요약은 빈칸 글 묶음이 같은데 번호만 다른 노트를 "빈칸 번호가 바뀐 것 같은 노트 n개"로 알리고, 그 결과 "새 번호 신규 카드 a장 · 학습에서 빠지는 옛 번호 카드 b장 (기록 · 일정 보존)"을 함께 보인다.
- 그래서 업데이트는 `save_note_fields` 를 쓰지 않는다 (빈칸이 줄면 카드를 지운다, I14). 필드를 쓰고 `add_missing_cards` · 빈칸 새 번호 카드만 만든다.

## 5. 내 덱 구조 · 설정

| 대상 | 처리 |
|---|---|
| 하위 덱 이동 · 덱 이름 | 내 것이다. 덱을 `anki_deck_id` 로 먼저 찾고 다음에 경로로 찾는다 (지금은 경로만 봐서, 이름을 바꾼 덱이면 새 덱이 생긴다). 이름 · 위치를 바꾸지 않는다. 만든 사람이 바꾼 덱 이름은 알리기만 한다 |

| 덱 중요도 · 카드 개별 중요도 · 취약 챕터 · 목표일 · 쉬기 · 하루 분량 | 앱 고유 데이터라 건드리지 않는다 |
| 기출 태그 · 출처 태그 | 2장 5 |

## 6. 흐름

1. **알아보기 (B2 사전 검사, B2-u0).** `inspect_anki` 의 `DeckStat.existing_notes` 가 1 이상이면 [업데이트로 가져오기] / [새 노트만 더하기]를 고르게 한다. 이 파일 노트의 절반 이상이 이미 있거나 같은 Anki 덱 id 의 덱이 있으면 업데이트가 기본이다. "새 노트만 더하기"는 지금 동작(I5)이다.
2. **먼저 받기.** 동기화가 연결돼 있으면 사전 검사 전에 받는다 (K32 와 같은 이유: 다른 기기의 수정을 알고 판정하고, 같은 새 노트가 두 벌 생기지 않게).
3. **업데이트 사전 검사** `inspect_update(path, deck_ids)`: 쓰지 않는 dry-run 이다. 요약 수 · 충돌 목록 · 유형 변화를 준다.
4. **요약 (B2-u)** → 충돌이 있으면 **충돌 검토 (B2-k · 카드 모양은 B2-kt)** → [업데이트 적용]. 사용자 요청(2026-10-18): 적용 전 요약에서 영향을 모두 확인할 수 있어야 한다. 요약에 보이는 것: 새 버전으로 바뀌는 노트 · 합친 노트 · 충돌 · 내 수정을 지킨 노트 · 새 노트(카드 수) · 새 버전에 없는 노트 · 내가 지운 노트 · 빈칸 번호가 바뀐 것 같은 노트와 그 결과(새 번호 신규 카드 n장 · 학습에서 빠지는 옛 번호 카드 n장, 기록 보존) · 내 모양을 지킨 노트 유형 · 새 필드 · 새 카드 종류 · 원본 없는 노트.
5. **적용.** `create_backup` → 한 트랜잭션 (멈추면 아무것도 바뀌지 않는다, I36) → **결과 (B3-u)**.
6. **되돌리기.** 1단계는 적용 전 자동 백업과 [백업으로 복구]다 (I35, 동기화 중이면 다음 받기에서 다시 맞춘다 K35). 복구는 DB 전체라 업데이트 뒤의 학습 · 수정도 함께 돌아간다는 것을 문구에 쓴다. 업데이트 단위 되돌리기는 2단계다 (DU16, 사용자 결정 2026-10-18).

## 7. 동기화 · 기존 결정과 맞추기

- **적용은 이 기기의 편집이다.** 트리거가 `sync_outbox` 에 쌓고, HLC 는 적용한 순간에 정한다 (K28). 패키지 mod 시각 같은 다른 HLC 는 쓰지 않는다: 이 기기의 그 열 HLC 보다 작으면 자기 자신에게 진다.
- **다른 기기가 같은 노트를 아직 올리지 않은 채 고쳤다면** 열마다 나중에 고친 쪽이 이긴다 (K28). 업데이트를 나중에 적용했으면 업데이트가 이기고, 그 기기의 수정은 K7 기록에 30일 남는다 ([이 버전으로 바꾸기]). 그 기기의 수정이 나중이면 그 수정이 이기고, 다음 업데이트에서 "내 수정"으로 지켜진다. 6장 2 "먼저 받기"가 이 창을 줄인다 (오프라인 편집은 남는다).
- **두 기기가 같은 파일로 따로 업데이트하면** 판정 · 값이 같아 겹친 노트는 내용이 같다 (K7 이 생기지 않는다). 새 노트는 guid 가 지금 동기화의 자연 키가 아니라서(처음 합칠 때만, K13 · `natural_match`) 두 벌이 된다. 지금 "다시 가져오기"에도 있는 문제다. 1단계는 먼저 받기로 피하고, guid 를 늘 자연 키로 하는 것은 K13 을 바꾸는 일이라 따로 한다.
- 사라진 노트를 사용자가 지우면 K29 그대로다 (다른 기기가 나중에 고쳤으면 남는다).
- 새 필드 · 새 카드 종류는 노트 유형 편집과 같은 함수(`field_ids`, ord 몫)로 더해야 K39 가 지켜진다. 받은 기기가 빠진 카드를 만들어도(K38) 자연 키(노트 + ord)로 한 장이 된다.
- **NT59 (Q2-08 · Q2-13).** 기준이 없을 때는 그대로 쓴다. 기준이 있으면 "기준에 있고 우리에 없음 = 내가 지움"이 Q2-08 과 같은 뜻이고, "기준에 없음 = 새로 생김"만 새로 더한다. Q2-13 의 숨긴 자리 넣기도 그대로다.
- I5 는 "새 노트만 더하기" 모드로 남는다. I79 · A4 · I85 · I86 · IT32(T2-02) · N9 · I24 는 그대로다.

## 9. 1단계 구현 (2026-10-18)

코드: `src-tauri/src/import/deck_update.rs` (판정 · 적용 · 원본, import.rs 의 자식 모듈이라 패키지 읽기 · 미디어 · 덱 함수를 그대로 쓴다). 결정은 DU20–DU27.

**원본 저장.** 1장 그대로 `note.origin` · `note_type.origin` 열 (db.rs migrate, NULL 허용, 동기화 대상 표의 열이라 raw_cols 로 따라간다) + 기기 안 표 `origin_gone(guid, at)` 와 트리거 `note_origin_gone` (`OLD.origin IS NOT NULL AND OLD.anki_guid IS NOT NULL`). 지금 가져오기(`import_anki`)도 새 노트 · 새 유형에 원본을 쓴다 (미디어 이름 바꾸기 뒤). 예전에 가져온 노트 · 유형은 채우지 않고 업데이트 때 어림한다 (DU18 · DU22). `wipe_all` 은 `origin_gone` 도 비운다.

**사전 검사 = 적용.** `run` 하나가 한 트랜잭션에서 모두 하고, 사전 검사면 되돌린다 (미디어 파일만 쓰지 않는다). 그래서 요약의 수가 곧 적용 결과이고, 고른 것(choices)을 넘기면 그대로 반영한 요약이 나온다 (DU20).

**명령 (화면이 쓴다).**

| 명령 | 입력 | 출력 |
|---|---|---|
| `inspect_anki` (기존) | path, voices | `AnkiPreview` 에 `update: UpdateHint \| null` 추가 (이미 있는 노트가 없으면 null) — B2-u0 |
| `inspect_update` | path, deck_ids?, choices?, voices? | `UpdateSummary` (쓰지 않는다) — B2-u · B2-k · B2-kt |
| `apply_update` | path, deck_ids?, choices?, voices? | `UpdateSummary` + `backup` (적용 전 백업 경로) — B3-u |

- `choices = { take_new: [노트 id…], new_looks: [[노트 유형 id, ord | null]…] }`. 기본(빈 값)은 모두 내 것 · 내 모양. `take_new` 는 그 노트의 충돌한 필드에만, `new_looks` 의 ord null 은 CSS.
- `UpdateHint = { notes, existing_notes, known_decks: [덱 이름], suggested }`. suggested = 절반 이상이 이미 있거나 같은 Anki 덱 id 의 덱이 있다.
- `UpdateSummary` (부록 A B2-u 의 줄 순서): `hint` · `changed` (새 버전으로 바뀌는 노트) · `merged` · `conflicts[]` (`note_id, title, deck, fields[{slot, name, mine, new}], auto_new, auto_mine, take_new, no_base`) · `mine_kept` · `same` · `new_notes` · `new_note_cards` · `missing_notes` · `missing_card_ids` ([카드 목록에서 보기]) · `gone` · `cloze{renumbered_notes, new_cards, emptied_cards}` · `new_cards` (이미 있는 노트에 생기는 카드 전부) · `emptied_cards` (앞면이 비어 학습에서 빠지는 카드 전부) · `types[]` (`note_type_id, name, created, no_base, new_fields, renamed_fields, removed_fields, new_templates, new_template_cards, removed_templates, updated_looks, looks[{ord, name, mine_front, mine_back, new_front, new_back, take_new}]`) · `kept_looks` · `no_base` · `other_type` · `media_new` · `media_renamed` · `reviews_skipped` · `issues[]` · `backup` · `roots`.

**화면의 명령 순서.**
1. `inspect_anki(path)` → `update` 가 있으면 B2-u0 고르기 (기본 = `suggested`). [새 노트만 더하기] 는 지금의 `import_anki` 그대로.
2. 동기화가 연결돼 있으면 (`sync_status().connected && enabled`) `sync_now()` → `sync_status().state` 가 `idle` (또는 `offline` · `error` 면 경고 한 줄 뒤 계속) 이 될 때까지 기다린다. 받기가 DB 를 잠그므로 3 과 겹치지 않는다.
3. `inspect_update(path, deck_ids)` → B2-u 요약. 충돌이 있으면 B2-k · B2-kt 에서 고르고 `inspect_update(path, deck_ids, choices)` 로 요약을 다시 받는다.
4. `apply_update(path, deck_ids, choices)` → B3-u. 백업 → 한 트랜잭션. 동기화는 다음 올리기에 실린다 (트리거가 남긴 변경, HLC 는 적용한 순간 K28).

**메모와 달라진 점.** ① `note_type.origin.f` 형식 (위 1장, DU21). ② 원본 없는 예전 유형에서 모양(앞 · 뒷면 · CSS)이 다르면 충돌로 보고 내 모양을 지킨다: [새 모양으로]로 고를 수 있다 (2장 6 "지금처럼 덮지 않는다"를 지키면서 고를 길을 남김, DU22). ③ [복습 기록도 옮기기]는 1단계에 없다 (`reviews_skipped` 로 수만, DU23). ④ 새 카드 종류는 이 유형의 모든 노트(이번 파일에 없는 노트 포함)에 카드를 만든다 (노트 유형 편집과 같다, DU24). ⑤ 미디어는 이번 노트 · 유형이 쓰는 것만 다룬다. 이름이 겹치는 파일만 풀어 비교하고 신형 패키지의 sha1 은 쓰지 않았다 (DU24). ⑥ 진행 표시 · 취소 이벤트는 없다 (DU26). ⑦ 이 작업 중 찾은 지금 가져오기의 버그(같은 모델 id 의 빈칸 유형에 다시 가져오면 새 노트가 모두 빠진다)를 고쳤다 (DU27).
