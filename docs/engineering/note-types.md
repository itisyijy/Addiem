# 노트 유형 · 카드 템플릿 (8.1, 1단계 엔진)

2026-10-16. 화면은 2단계(디자인 뒤). 코드: `src-tauri/src/notetype.rs`, 결정 행은 DECISIONS NT 섹션.

## 1. 앱 유형 식별 — 이름에서 뗀다

- `note_type.native_kind` (basic · reversed · cloze · written · list · choice · io, 그 밖은 NULL). 시드 · 조회(`native_type_id`) · 내보내기 stock 표시 · CSV 의 "필드 그대로" 판정 · 동기화 자연 키가 이 열을 본다.
- 기존 DB 는 `seed_note_types` 가 시드 전에 이름으로 한 번 채운다 (`anki_model_id IS NULL` 행만, 멱등). Drive 의 옛 스냅샷을 받은 뒤(Join::Take)에도 같은 길이라 두 벌이 생기지 않는다.
- 앱 유형은 읽기 전용: 바꾸는 명령은 모두 `native_kind IS NOT NULL` 이면 거부한다. 고치려면 [복제해서 고치기].
- **복제는 basic · reversed · cloze · written 과 가져온 유형만.** list · choice · io 는 학습 화면이 템플릿 대신 필드로 그리고(Q16, M) 전용 편집기가 붙어 있어, 복제본을 템플릿 경로로 그리면 같은 유형인데 다르게 보인다. 복제 버튼 자체를 없앤다 (`cloneable`).
- `note_type.user_made = 1` 은 앱에서 만든 사용자 유형(복제본). "가져온 유형" = 모델 id 가 있고 user_made 0.

## 2. 사용자 유형 id

- 만들 때 Anki 식 `anki_model_id` 를 바로 정한다: 지금 ms, 이미 있으면 +1 씩. 동기화 자연 키가 이름이 아니라 모델 id 라 두 기기에서 따로 만든 같은 이름 유형이 합쳐지지 않는다. 내보내기는 이 id 를 그대로 쓴다 (`created_at + rowid` 대체는 앱 기본 유형에만 남는다).
- 앱 유형을 복제하면 필드를 화면 이름으로 만든다 (질문과 답변 · 양방향: 질문 / 답변, 빈칸: 본문 / 추가 설명, 서술형은 그대로). 템플릿 참조도 `rename_refs` 로 같이, 그리고 쉬운 편집 모양으로 새로 써(`build_layout`) 처음부터 모든 줄이 줄 상자 · 노트 CSS 에 줄 상자 CSS (쉬운 편집이 못 읽는 서술형은 그대로). 원본과 그 카드는 그대로 (NT54 · NT57). 사용자 · 가져온 유형 복제는 그대로 복사한다.
- 복제는 원본의 stock 표시를 물려받는다 (Anki 복제와 같다: Basic 복제본도 "기본값으로 되돌리기"가 보인다).
- 이름은 비울 수 없고 다른 유형과 같을 수 없다 (복제 기본 이름: 앱 유형은 "내 질문과 답변", 그 밖은 "X 복사본", 겹치면 " 2", " 3" …). 동기화로 같은 이름 두 개가 생기는 것은 그대로 둔다 (Anki 도 허용).

## 3. 필드 — 자리(slot) 고정

`note.fields` 배열의 위치를 다시 매기지 않는다. 열 단위 LWW 에서 다른 기기의 옛 배열이 이기면 어긋나기 때문이다.

- `note_type.fields` 는 지금처럼 자리별 이름 JSON 배열 (옛 앱도 읽는다). **지운 자리는 이름을 `""` 로 둔다.** 값은 노트에 남고, 화면 · 템플릿 · 내보내기에서 빠진다. 같은 이름을 다시 더해도 지운 자리와 겹치지 않는다.
- `note_type.field_order` = 보이는 순서 (자리 번호 JSON 배열, NULL = 자리 순서). 읽을 때는 `field_order` 의 살아 있는 자리, 그다음 거기 없는 살아 있는 자리를 자리 순서로 (`visible`). 그래서 `fields` 와 `field_order` 가 서로 다른 기기 것으로 합쳐져도 필드를 잃거나 지운 필드가 살아나지 않는다.
- 추가 = 끝에 새 자리. 노트는 고치지 않는다 (짧은 배열의 없는 칸 = 빈 값).
- 이름 바꾸기 = 이름 + 그 유형 템플릿의 `{{X}}` `{{#X}}` `{{^X}}` `{{/X}}` `{{필터:X}}` 를 같이 고친다.
- 순서 바꾸기 = `field_order` 만.
- 지우기 = 템플릿이 참조하면 거부 (화면이 먼저 템플릿에서 빼고, 빼는 저장의 확인에 `empty_front_count` 를 쓴다).
- 화면 경계: `note_edit` 는 보이는 순서의 names · values 와 `slots` 를 준다. `update_note` 는 `slots`(없으면 지금 보이는 순서)로 자리에 되돌려 쓴다. 앱 유형 · 손대지 않은 가져온 유형은 보이는 순서 = 자리 순서라 지금과 같다. 목록 · 선택형 · 그림 가리기 편집은 자리 순서 그대로 쓴다.
- 첫 칸 검사("첫 칸을 비울 수 없어요")는 보이는 첫 필드다. 앱 기본 유형과 새 노트 추가에만 쓴다: 사용자 · 가져온 유형의 기존 노트 편집은 첫 칸이 비어도 저장한다 (NT64, Anki 와 같다).
- 내보내기: 보이는 순서로 Anki 필드를 쓰고 노트 값을 그 순서로 다시 배열한다. 가져오기: 새 유형의 자리 = Anki ord. 이미 있는 유형(같은 모델 id, 사용자 편집을 덮지 않는다)에 들어오는 노트는 필드 이름으로 자리를 찾고, 없으면 같은 위치의 보이는 자리로.
- 자리마다 id: `note_type.field_ids` (JSON, 앱에서 더한 필드만 "더한 시각-기기", 처음부터 있던 자리는 "", 없으면 NULL). 두 기기가 같은 자리에 따로 더한 필드를 동기화가 가린다 (9장).

## 4. 템플릿 (카드 종류)

- `ord` 는 정체성이다. 다시 매기지 않는다 (FSRS 기록이 엉뚱한 카드에 붙는다).
- 추가 = `max(next_ord, max(ord)+1)`. `note_type.next_ord` 에 다음 번호를 남겨 지운 번호를 다시 쓰지 않는다 (다른 기기에 남은 옛 카드가 새 템플릿에 붙지 않게). 동기화를 켰으면 그 값 이상에서 이 기기 몫(ord mod 2^16 = 기기 uid 끝 4자리)인 가장 작은 번호 (9장). 화면은 ord 를 보이지 않고 ("카드 1" 은 순서), 내보내기는 0 부터 다시 센다. 빈칸 유형은 템플릿을 더할 수 없다 (Anki 와 같다).
- 카드 생성 규칙 (Anki "앞면이 비지 않으면"): 실제 값으로 그린 앞면이 비지 않고, 모든 필드를 비운 앞면과 다르면 카드가 있다 (고정 글자만으로는 생기지 않는다). 빈칸 유형은 값의 빈칸 번호마다. 템플릿 추가 · 사용자 유형 노트 추가 · 일반 유형 노트 편집(만들기만, 지우지 않는다. Anki 와 같다)에서 쓴다. 새 카드의 덱은 그 노트의 첫 카드 덱.
- 삭제 = 그 ord 카드 삭제. 복습 기록은 다른 카드 삭제와 같이 `card_id = NULL` 로 남긴다 (A4, 히트맵은 사실로 남는다). `delete_template(dry_run)` 이 카드 수 · 기록 수를 먼저 준다. 마지막 하나는 지울 수 없다.
- 저장 검사 (`check_template`): 빈칸 유형의 앞면은 `{{cloze:` 필수, 일반 유형은 금지 (빈칸 여부를 템플릿으로 바꾸지 못하게). 앞면에 필드 하나 이상. 없는 · 지운 필드 참조 금지. `{{#X}}`/`{{^X}}` 와 `{{/X}}` 짝. 이름은 비지 않고 겹치지 않는다.
- 카드 → 템플릿 고르기는 한 곳 (`notetype::TEMPLATE_OF_CARD`, 빈칸이면 ord 0): 8곳에 복사돼 있던 `nt.name='Cloze' OR qfmt LIKE` 를 바꿨다. 빈칸 유형 판정도 `notetype::IS_CLOZE` 하나 (앱 Cloze 도 qfmt 로 걸린다).
- 바꿀 때마다 `note_type.updated_at` · `card_template.updated_at` 을 올린다 (Anki mod, 동기화).

## 5. 렌더링 · 이름 키

- `note_field_names` 는 노트 유형 **id** 키 (전에는 이름 키라 가져온 "Basic" 과 앱 Basic 이 서로 덮였다). 지운 자리는 맵에 넣지 않는다.
- 미리보기는 render.rs 그대로 (`preview_template`).

## 6. 쉬운 편집기 구조

`template_layout(qfmt, afmt)` → 구조 또는 None (= HTML 전용). 칸: `field`, `cloze`, `type`(입력칸), `tts`, 뒷면 첫 칸만 `front_side`(+ `<hr id=answer>`). `build_template_layout` 은 정해진 모양으로 쓴다: 필드 · 빈칸은 한 줄에 하나(`<br>` 하나), 입력칸 · 읽어주기는 앞 칸에 붙인다, FrontSide 뒤 `<hr id=answer>`. **다시 쓴 것이 같게 보일 때만 구조로 연다** (공백 · 줄바꿈 글자 차이만 받는다). 그래서 한 줄에 필드 여럿 · 굵게 · 색 · 조건 구간 · 빈 줄은 HTML 전용이다 (디자인 NT 결정과 같다). 앱 Basic · 앞뒤 · Cloze 템플릿은 바이트 그대로 왕복한다. 서술형 뒷면(조건 구간 · div)은 HTML 전용. Anki 가 만든 Basic 은 공백만 정리되므로, 쉬운 편집기에서 바꾸지 않았으면 저장하지 않는다(`apply_edit` 가 바뀐 템플릿만 쓴다).

**줄 모양 (2단계 A, 디자인 NT5 S/M/L · 왼쪽/가운데).** 필드 · 빈칸 칸에 `look: { size: s|m|l, align: left|center }` (없으면 그 면의 기본: 앞면 L · 가운데, 뒷면 M · 왼쪽 = 학습 화면의 질문 30px · 답 20px). 쉬운 편집이 쓰는 필드 · 빈칸 줄은 **기본 모양이어도 늘** `<div class="nt-크기 nt-정렬">칸…</div>` 로 감싸고 (입력칸 · 읽어주기는 상자 안에 붙는다), 상자 앞뒤에는 `<br>` 을 쓰지 않는다. 그래서 학습 화면(`.study__q` 가운데) · Anki(`.card` 가운데) · 덱 CSS 어디서든 줄 설정이 이긴다. 읽을 때는 감싼 줄과 감싸지 않은 줄(앱 기본 유형 · 예전 템플릿, 그 면의 기본 모양)을 둘 다 받는다. 앱 기본 유형은 읽기 전용이라 다시 쓰지 않는다. 클래스 CSS 는 `LAYOUT_CSS`(`div.nt-s` 13px · `div.nt-m` 20px · `div.nt-l` 30px · text-align, `div` 를 붙여 덱 CSS 의 `.card div` 와 같은 무게에서 뒤에 와 이긴다) 이고 **노트 유형 CSS 안에 둔다**: 템플릿이 상자를 쓰는데 CSS 에 그 첫 줄 주석이 없으면 저장할 때 끝에 붙인다. 학습 화면은 노트 CSS 를 카드 안에 가두므로(`scopeCss`) 앱 화면에는 그 카드에만 걸린다. Anki 내보내기는 CSS 가 이 덩어리뿐이면 빈 CSS 처럼 Anki 기본 CSS 를 쓰고 그 뒤에 붙인다 (앱 유형 복제본은 CSS 가 비어 있다). 모르는 클래스 · 상자 밖에 붙은 입력칸 · 상자 안 필드 둘은 HTML 전용.

**HTML 전용 이유.** `template_layout` 은 구조 또는 `Err(이유)`: 처음 걸린 것 하나를 명사구로 ("뒷면에 조건문 {{#예문}}", "앞면에 직접 쓴 <div> 태그", "앞면 한 줄에 필드 여러 개", "앞면에 빈 줄", "뒷면 중간의 {{FrontSide}}" …). 화면이 "…이/가 있어 쉬운 편집이 그대로 옮기지 못해요. 고쳐도 HTML은 그대로 남아요." 로 쓴다. 상세(`note_type_detail`)도 카드 종류마다 `reason` 을 준다.

**편집기 저장.** 화면은 초안(필드 보이는 순서 · 자리, 카드 종류 · 템플릿, CSS)을 들고 있다가 `save_note_type(edit, dry_run)` 한 번으로 쓴다 (한 트랜잭션). 순서: 필드 이름(템플릿 참조도) → 새 필드 → 바뀐 템플릿 저장 · 새 카드 종류 → 빠진 카드 종류 지우기 → 빠진 필드 지우기 → 순서 → CSS. dry_run 은 같은 일을 하고 되돌려 확인 창의 수를 준다: 앞면이 비게 되는 카드(저장 전후 앞면 비교라 이름을 바꾸거나 더한 필드도 맞다), 지우는 카드 종류마다 카드 · 기록 · 노트 수, 숨기는 필드마다 내용이 있는 노트 수, 새로 생기는 카드 수. 지우는 저장이면 화면이 `create_backup` 을 먼저 부른다. 편집 중 필드 이름을 바꾸면 화면이 `rename_field_refs` 로 초안 템플릿도 고친다. 미리보기는 `preview_template(…, names)` 로 초안 필드 이름을 쓴다 (값은 `note_type_samples` 의 자리 값, 새 필드는 이름 샘플). 한계: 지운 필드와 같은 이름을 같은 저장에서 다시 더하거나 두 필드 이름을 맞바꾸면 "이미 있어요" 로 거부한다 (두 번 나눠 저장).

**앞면이 빈 카드 (NT49, 사용자 확인 대기).** `notetype::Fronts` 가 노트 유형마다 앞면 템플릿이 쓰는 자리를 한 번 읽어 두고, 카드마다 그 자리 값만 본다 (렌더하지 않는다): 일반 카드는 그 필드가 모두 비었으면(`render::is_blank`, 그림 · 소리는 비지 않았다), 빈칸 카드는 그 번호가 `{{cloze:}}` 필드에 없으면 빈 앞면. 조건 구간이 숨기는 필드는 비지 않은 것으로 본다 (빼는 쪽으로는 틀리지 않는다). `commands::load_cards` 가 `queue::Card.front_empty` 를 채워 큐가 빼고(오늘의 학습 · 홈 · D1 · 내일 예정 · 계획, `Card::plays`), `cram::items` 가 압축 · 혼합 회독에서 뺀다. SQL 로 세는 남은 신규(덱 상세 · 목표 안내 · 설정 미리보기 · 계획 고정)는 `notetype::new_left` 가 같은 규칙으로 뺀다 (NT63). 상태 · 일정은 그대로라 필드를 채우면 바로 다시 나온다. 카드 목록은 "앞면 빔" 배지.

## 7. 카드 유형 추천 (규칙만)

`suggest_card_kind(text, answer)` → `cloze` | `choice` | `list` | `occlusion` | 없음. 순서: `{{c1::` → 빈칸, 괄호 빈칸 `( )` `[ ]` `___` 은 답 칸(answer)에 글이 있을 때만 빈칸 (화면이 `{{c1::답}}` 으로 바꾼다), ①②③④(또는 "1) 2) 3) 4)") 보기 4개 이상 → 선택형, 번호 · 불릿 줄 3개 이상 → 목록 (quality.rs `item_marker` 재사용), 글자 없이 그림만 → 그림 가리기. 자동 변경 없음 (2단계 UI 의 제안 칩).

## 7-1. 덱의 처음 유형

디자인 NT12: 덱마다 마지막에 쓴 유형은 화면이 이 기기에만 기억한다. 처음이면 `deck_note_types(deck_id)` 의 첫째 = 그 덱(하위 덱 포함) 노트가 가장 많이 쓰는 유형 (같으면 최근). 목록 전체는 NT11 [⋯] 의 "이 덱이 쓰는 노트 유형 먼저".

## 8. 동기화

- 자연 키: 모델 id 가 있으면 모델 id, 없고 `native_kind` 가 있으면 `native_kind`, 둘 다 없으면 예전처럼 이름 (옛 앱이 보낸 기본 유형).
- 새 열(native_kind · user_made · field_order · next_ord)은 raw_cols 로 따라간다. 모두 NULL/0 허용이라 옛 앱은 건너뛴다.
- 엔진 테스트: 필드 추가 ∥ 노트 편집, 필드 이름 바꾸기 ∥ 노트 편집, 템플릿 추가(카드 생성) ∥ 노트 편집, 두 기기의 같은 이름 사용자 유형.
- 지우기 (K37): 카드 종류는 노트 유형의 일부라 남긴 유형과 함께 남는다. 남은 카드는 그 카드 종류(노트 유형 + ord)를 붙잡는다: 카드 종류를 지우는 사이 다른 기기가 노트를 고쳤으면 그 노트 카드와 카드 종류가 함께 남는다 (고아 카드가 없다). 지운 기기 자신의 수정(빈칸을 지우는 같은 트랜잭션의 노트 수정)은 지우기를 막지 않는다.
- 받은 뒤 카드 만들기 (K38): 노트를 쓴 기기가 모르던 카드 종류를 받거나, 카드 종류(앞면)를 쓴 기기가 모르던 노트를 받으면 빠진 카드를 만들어 올린다. 따로 만든 같은 카드는 자연 키(노트 + ord)로 한 장.
- 내보내기 (NT58): 카드 종류가 없는 카드 · 템플릿 없는 유형은 빼고 알린다 (Anki 가 패키지를 거부한다).
- 테스트 (sync/tests.rs): `type_deleted_while_note_added_elsewhere_keeps_its_card_types`, `card_type_deleted_while_note_edited_elsewhere_leaves_no_orphan`, `cloze_removed_in_the_same_edit_stays_removed`, `card_type_added_while_note_added_elsewhere`, `card_types_added_on_both_devices_both_stay`, `fields_added_on_both_devices_keep_values_apart`, `same_template_edited_on_both_devices_keeps_the_losing_version`.

## 9. 두 기기에서 같은 유형의 구조를 고칠 때 (QA Q2-05 · Q2-06, K39)

**문제.** 열 단위 LWW 에서 두 기기가 같은 유형에 동시에 카드 종류를 더하면 같은 ord (자연 키 `(note_type_id, ord)` 로 한 행에 합쳐져 한쪽 정의가 사라지고 그 기기 카드가 다른 템플릿에 붙는다), 필드를 더하면 같은 자리 (`fields` 배열이 통째로 한쪽 것이 되고, A 가 뒷면에 넣은 값이 B 의 필드 이름으로 앞면에 보여 답이 노출된다).

| 대안 | 방법 | 판단 |
|---|---|---|
| (a) 기기마다 겹치지 않게 매기기 | ord · 자리를 기기마다 다른 몫에서 | **ord 는 고른다.** ord 는 정체성일 뿐이고 (화면은 순서로 "카드 1", 내보내기는 0 부터 다시 센다) u32 라 빈 번호가 많아도 된다. 동기화 중이면 `max(next_ord, max+1)` 이상에서 ord mod 2^16 = 기기 uid 끝 4자리(16진수)인 가장 작은 수. 겹칠 확률은 기기 쌍마다 1/65536. **자리는 안 된다**: 자리는 `note.fields` 배열 위치라 큰 몫이면 노트마다 빈 칸 수만 개가 생긴다 (빈 자리 자체는 지운 자리처럼 "" 라 괜찮다) |
| (b) 합칠 때 알아보고 진 쪽을 새 자리로 | 충돌을 알아보고 옮긴다 | **필드는 고른다.** 자리마다 id (`field_ids`, 더한 시각-기기) 를 두고 `fields` · `field_ids` 를 자리마다 합친다: 같은 id 는 나중 쪽 이름, 한쪽에만 있는 자리는 그대로, 같은 자리에 id 가 다르면 나중 쪽이 그 자리를 갖고 진 쪽 필드는 끝 새 자리로 (나중 쪽이 이미 옮겨 두었으면 그 자리로, 이름까지 같으면 같은 필드). 두 기기가 같은 (이긴 쪽, 진 쪽) 을 보므로 결과가 같고, 받은 값과 다르면 이 기기의 변경으로 올린다. 진 쪽 노트 값은 "노트 내용의 HLC 가 진 기기 것이고 그 필드를 더한 시각 뒤"인 노트만 새 자리로 옮긴다 (그 전 노트 · 이긴 기기 노트는 그 자리에 진 쪽 값이 없다). 카드 종류에 쓰면 카드마다 어느 기기 정의로 만들었는지 가려야 해서 (a) 로 피했다 |
| (c) 구조 편집 전후 받기 · 올리기 강제 | Anki 의 스키마 변경 = 전체 동기화처럼 창을 줄인다 | 고르지 않았다. 창이 줄 뿐 오프라인 편집에서는 그대로 생기고, 막으면 오프라인에서 필드를 더할 수 없다. 남는 경우를 막는 장치는 어차피 필요하다 |

**어느 쪽이든 막는 것.**
- 답 노출: (b) 로 진 쪽 값이 진 쪽 필드 아래로 가서, 그 필드를 쓰는 진 쪽 템플릿 면에만 나온다. 템플릿이 참조하는 없는 필드는 빈 값으로 그린다 (render.rs 그대로).
- 말없는 정의 손실: 진 쪽이 자리를 옮긴 것과, 이 기기 것이 올라가기 전에 받은 쪽이 같은 곳(카드 종류 앞 · 뒷면 · 이름, CSS, 유형 이름, 필드 이름)을 고친 것은 `sync_type_conflict` 에 진 쪽 내용을 30일 남긴다 (K7 처럼). 노트 유형 편집기가 "다른 기기와 동시에 고친 내용 N건은 나중에 고친 쪽으로 맞췄어요 · [진 쪽 보기]" 로 진 쪽 HTML 을 보인다.
- 열어 둔 편집기 (Q2-07, NT60): 연 때의 정의 지문이 다르면 저장하지 않는다 (낡은 초안에 없는 다른 기기 필드 · 카드 종류를 지우게 된다).

**한계 (ponytail).** 진 쪽 정의를 먼저 받은 세 번째 기기가 쓴 노트 값은 옮기지 않는다. 두 기기가 같은 이름의 필드를 다른 자리에 동시에 더하면 이름이 겹친 채 남는다. 진 쪽 기록은 먼저 받은 기기에만 남을 수 있다 (두 기기가 서로 받기 전에 동시에 올리면 남지 않는다). `field_order` 는 열 그대로 겨룬다 (`visible` 이 빠진 자리를 끝에 붙여 필드는 잃지 않는다).
