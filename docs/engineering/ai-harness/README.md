# AI 작업 Harness

## 문서 상태

- 버전: v0.1
- 상태: **작성 중.** 작업별 문서를 하나씩 쓰고 있다 (순서는 아래 표). 첫 작업(채점 보조)까지 썼다
- 관련: [DECISIONS](../../DECISIONS-PENDING-REVIEW.md), [MVP 범위 8.1–8.4](../../product/mvp-scope.md), [개발 안내](../development.md)

ChatGPT 를 쓰는 작업마다 Spec → Skill → Subagent → Workflow → Hook → Checklist 순서로 설계를 다시 적는다.
형식 검사와 사용자 승인은 이미 코드에 있다. 이 문서들이 채우려는 것은 **내용이 맞는지 확인하는 장치**와 **실제 모델 출력을 재는 수단**이다.

> 각 절 끝의 "현재 코드와 다른 점"이 코드 반영의 작업 목록이다. 반영을 마친 항목은 지운다.
> 반영이 끝난 작업은 코드가 정본이고, 코드를 바꾸면 그 작업의 문서도 바꾼다.

## 6요소를 앱에 대응시키는 기준

Addiem 은 Rust 코드가 ChatGPT 를 한 번 호출하고 그 출력을 검사하는 구조다. 에이전트 플랫폼의 용어를 아래처럼 읽는다.

| 요소 | 뜻 | 문서에 쓰는 것 | 대응 코드 |
|---|---|---|---|
| Spec | 목표 · 맥락 · 범위 · 제약 · 출력 형식 · 성공 기준 | 같은 6항목. 성공 기준을 먼저 쓰고 ID 를 붙인다 | (문서) |
| Skill | 반복 작업의 절차 | 모델에게 주는 지시문과 출력 스키마 | `*_INSTRUCTIONS`, `*_schema` |
| Subagent | 입력 형식 · 출력 형식 · 도구 권한 · 독립 컨텍스트 | 호출 한 번의 경계: 보내는 글의 범위와 상한, 받는 형식, 모델이 할 수 없는 것 | `*_input`, `request_body`, `clip` |
| Workflow | 실행 순서 · 입출력 · 조건 분기 | 버튼을 누른 뒤의 단계, 분기, 종료 상태, 사용자 승인 지점 | `*_blocking`, 화면 상태 |
| Hook | 이벤트에 무조건 실행되는 장치 | 응답을 받을 때와 승인할 때 코드가 항상 돌리는 검사 | `parse_*`, `apply_*` |
| Checklist | 성공 기준의 실행 가능한 버전 | 성공 기준 ID 마다 확인 방법과 위치 | `#[test]`, 평가 테스트 |

지시문에 "~하지 마세요"로 적은 규칙은 모델이 건너뛸 수 있다. 코드로 확인할 수 있는 규칙은 Hook 으로 옮기고, 옮길 수 없는 것만 지시문에 남긴 뒤 평가셋으로 잰다.

## ID 규칙

`<작업>-<종류>-<번호>` 로 쓴다. 번호는 다시 쓰지 않는다 (지운 번호는 비워 둔다).

| 작업 | 접두어 | | 종류 | 뜻 |
|---|---|---|---|---|
| 채점 보조 | `GR` | | `SC` | 성공 기준 (Spec) |
| AI로 확인 | `CK` | | `H` | 코드 검사 (Hook) |
| 카드 초안 | `DR` | | | |
| 오답 보기 | `DS` | | | |
| 성격별로 묶기 | `RG` | | | |

Checklist 표는 `SC` 마다 확인 방법을 하나 이상 잇는다: **테스트**(단위 테스트 이름), **평가셋**(실제 모델 출력을 재는 테스트와 기준 수치), **사람**(화면에서 사용자가 확인). 돌리지 못한 확인은 통과가 아니라 **미실행**으로 적는다.

## 다섯 작업에 공통인 것 (현재 코드)

- **호출은 한 곳을 지난다.** `ai::generate` (`src-tauri/src/ai.rs`). 지시문(`instructions`)과 사용자 입력(`input`)을 나눠 보내고, `store: false`, 출력은 `json_schema`(strict)로 받는다. 형식 지정을 받지 않는 모델이면 형식 없이 다시 보낸다.
- **모델은 고정돼 있지 않다.** 저장해 둔 모델을 쓰고, 없거나 쓸 수 없으면 계정의 모델 목록에서 작은 모델부터 고른다.
- **결과는 제안이다.** 카드와 복습 일정을 바꾸는 것은 사용자가 승인한 명령뿐이다.
- **형식이 어긋나면 전부 버린다.** `parse_*` 가 `AiError::BadOutput` 을 낸다 (오답 보기와 "AI로 확인"의 확인 물음만 항목 단위로 버린다). Rust 쪽에는 형식 오류 뒤의 자동 재요청이 없다.
- **실패 기록은 두 작업만 남긴다.** `ai-errors.log` 에 쓰는 것은 `ai_check_card` 와 `rag_grade` 다 (`ai::log_failure`).
- **가짜 응답 모드.** debug 빌드에서 `ADDIEM_AI_FAKE` 로 계정 없이 보내는 중 · 오류 · 결과 화면을 본다. 단위 테스트는 이 가짜 출력과 손으로 쓴 출력으로 `parse_*` 를 검사한다. 실제 모델 출력을 재는 길은 로컬 모델(`eval83`)과 채점 보조(`ADDIEM_GRADE_EVAL`, grade.md 6.3)에 있다.
