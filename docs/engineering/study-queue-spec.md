## 1. 이 문서의 범위

### 정의하는 것

- 오늘 큐에 무엇이 들어가는가
- 어떤 순서로 보여주는가
- 신규 카드를 하루에 몇 장 투입하는가
- 반복 실패 카드를 언제 어떻게 빼내고 되돌리는가

### 정의하지 않는 것

- 카드 한 장의 다음 복습 간격 (SRS 라이브러리 담당. ADR 0001 7장)
- 난이도와 안정성 갱신 (같음)
- 화면 배치와 문구 (화면 흐름 문서)

## 2. 용어

| 용어 | 정의 |
|---|---|
| **오늘 / 학습일** | 새벽 4시를 경계로 한 날짜. `2026-09-20 03:59`는 `2026-09-19`다 |
| **세션** | 학습 시작부터 이탈까지. 하루 경계를 넘으면 종료한다 |
| **학습 가능 일수** | `목표일 - 오늘 + (당일 포함이면 1)`. 오늘을 포함한다 |
| **주 흐름** | 오늘 큐에서 순서대로 제시되는 카드들 |
| **보류** | 주 흐름에서 잠시 빼낸 상태. 버리는 것이 아니다 |
| **밀린 복습** | 예정일이 오늘보다 **이전**인 복습 카드 |
| **예산 덱** | 신규 카드 상한을 가진 덱. 하위 덱은 여기서 상속한다 |

### 하루 경계를 새벽 4시로 정한 이유

자정으로 하면 밤 11시 50분에 시작한 학습이 10분 뒤 "다음 날"이 된다. 하루치 분량을 두 번 받고, 연속 학습일이 끊긴다. Anki의 기본값도 같다.

### 세션 판정

| 상황 | 같은 세션인가 |
|---|---|
| 학습 중 앱을 껐다가 10분 뒤 다시 켠다 | **예** |
| 학습을 끝내지 않고 6시간 뒤 다시 켠다 | **예** (같은 학습일이면) |
| 하루 경계를 넘겨서 이어한다 | **아니오.** 경계에서 종료하고 새 세션 |
| 덱 A를 학습하다 덱 B 학습을 시작한다 | **예.** 덱이 아니라 학습 행위 단위다 |
| 오늘 예정을 다 끝내고 다시 학습을 시작한다 | **아니오.** 완료로 종료하고 새 세션 |

근거는 인터뷰다.

> 한 번 덱에 들어갔다가 나올 때까지를 하나의 세션이라고 봤을 때는...

덱 단위라는 사용자의 표현을 그대로 쓰지 않고 학습 행위 단위로 넓혔다. 여러 덱을 합쳐 학습하는 것이 MVP 6.6의 기능이라 덱 단위로는 세션이 정의되지 않는다.

## 3. 입력

| 입력 | 출처 |
|---|---|
| 학습일 | 현재 시각 + 하루 경계 |
| 덱 트리와 설정 | `deck`, `deck_config` |
| 카드 상태와 중요도 | `card_effective` 뷰 |
| 이전 세션의 보류 | `card.buried_until` (상태와 별개) |
| 학습할 덱 선택 | 사용자 (홈 또는 덱 상세) |
| 분량 조정 배수 | 사용자 (학습 시작 전 요약) |

## 4. 큐 구성

### 4.1 단계

```text
1. 후보 수집       상태별로 나눈다
2. 신규 목표량     예산 덱 단위로 계산한다
3. 정렬            그룹별 기준이 다르다
4. 상한 적용       밀린 복습이 오늘을 마비시키지 않게
5. 배치            복습을 비우고 신규로 간다
```

### 4.2 후보 수집

| 후보군 | 수집 조건 |
|---|---|
| 학습 중 | `state = 'learning'` |
| 보류 복귀 | `buried_until <= 오늘`. 상태는 보지 않는다 |
| 예정 복습 | `state in ('review','relearning')` 이고 `due_day = 오늘` |
| 밀린 복습 | 같은 상태이고 `due_day < 오늘` |
| 신규 | `state = 'new'` |
| **제외** | `state = 'suspended'`. 예외 없이 나오지 않는다 |
| **제외** | `due_day > 오늘`. 미래 예정은 오늘 큐에 없다 |
| **제외** | `buried_until > 오늘`. 보류 기간에는 상태와 상관없이 나오지 않는다 |

보류는 상태가 아니라 기간이다 ([스파이크 5](spike-05-fsrs.md) 결함 2). `buried_until` 이 있는 카드는 다른 후보군에 들어가지 않는다.

**형제 카드는 하루에 한 장이다** (DECISIONS I49). 빈칸이 아닌 노트의 카드는 같은 학습일에 하나만 큐에 오르고, 오늘 이미 평가한 노트의 카드도 다음 날로 간다. 앞선 후보군(보류 복귀 > 예정 복습 > 밀린 복습 > 신규)이 남는다. **학습 중 · 재학습 카드는 이 규칙으로 빠지지 않는다** (I80). 오늘 Again 을 받은 복습 카드는 자기 노트를 오늘 봤으므로, 빼면 재학습이 오늘 안에 다시 나오지 않는다.

**쉬는 덱**은 하위 덱까지 후보에서 뺀다. 다만 쉬는 덱(또는 그 안의 덱)을 직접 골라 학습하면 그 범위의 복습 후보(학습 중 · 보류 복귀 · 예정 · 밀린)는 모으고 신규만 모으지 않는다 (I84).

### 4.3 신규 목표량

MVP 범위 6.6의 확정 산식이다.

```text
권장 신규 = ceil(남은 신규 카드 수 / 남은 학습 가능 일수)
```

| 항목 | 결정 | 근거 |
|---|---|---|
| 보충 중요도 카드를 남은 신규에 포함하는가 | **포함한다** | 범위를 완주하는 것이 목표다. 순서만 뒤로 민다 |
| 소수점 처리 | **올림** | 내림하면 나머지가 마지막 날에 몰린다 |
| 학습 가능 일수가 0 | 남은 것을 전부 올린다 | 오늘이 마지막이다 |
| 학습 가능 일수가 음수 | 남은 것을 전부 올린다 + "목표일이 지났다" 표시 | 나누기 0을 피하고 사용자에게 알린다 |
| 상한과 충돌 | **상한이 이긴다.** 다만 "이대로면 목표일을 넘긴다"를 표시한다 | 조용히 목표를 포기하지 않는다 |
| 어제 못 채운 분량 | **이월하지 않는다.** 산식이 자동으로 반영한다 | 남은 카드가 줄지 않았으니 오늘 몫이 자연히 늘어난다 |

### 4.4 예산 덱 — 하위 덱마다 상한을 주지 않는다

**실제 데이터에서 발견한 문제다.** 실측 컬렉션은 덱이 140개(대부분 하위 덱)였다. 하위 덱마다 하루 20장을 주면 오늘 신규가 **1,699장**이 된다.

```text
규칙: 신규 예산은 설정을 가진 가장 가까운 조상 덱이 갖는다.
      아무도 설정이 없으면 최상위 덱이 갖는다.
```

같은 데이터에서 이 규칙을 적용하니 100장이 되었다.

하위 덱이 자기 설정을 가지면 그 덱은 따로 예산을 받는다. 시험 범위 중 한 챕터만 따로 관리하고 싶은 경우다.

### 4.5 정렬

MVP 범위 6.6의 확정 우선순위다.

```text
1. 복습 예정 카드
2. 핵심 신규 카드
3. 일반 신규 카드
4. 보충 신규 카드
```

그룹 내부 기준이다.

| 그룹 | 정렬 | 동점일 때 |
|---|---|---|
| 복습, 밀린 복습, 학습 중 | 예정일 오래된 순 | 중요도 높은 순 → 원래 순서 |
| 신규 | 중요도 높은 순 | 원래 순서 (Anki의 `due` 필드) |
| 보류 복귀 | 중요도 높은 순 | 원래 순서 |

| 확인 항목 | 결정 |
|---|---|
| 여러 덱을 합칠 때 덱 간 순서 | 덱을 섞지 않는다. 예산 덱 단위로 블록을 이어 붙인다 |
| 하위 덱의 원래 순서 유지 | 유지한다. `position`이 그 순서다 |
| 무작위 요소 | **넣지 않는다.** 같은 입력이면 같은 큐가 나와야 테스트할 수 있다 |

### 4.6 상한

| 항목 | 결정 |
|---|---|
| 상한은 신규에만 적용하는가 | 신규는 예산 덱 상한, 밀린 복습은 별도 상한 |
| 밀린 복습 하루 상한 | **200장.** 근거가 약하다. 실사용 후 조정한다 |
| 상한의 범위 | **하루 전체에 200장.** 오늘 이미 처리한 밀린 복습(`review_log.overdue`)만큼 줄어든다. 덱 하나만 학습할 때도 전체 계획에서 고른 200장 중 그 덱 몫만 나온다 (홈의 덱별 분량과 같게) |
| 예정 복습에 상한 | **없다.** 오늘 예정된 것은 오늘 보여준다 |
| 여러 덱 합산 시 | 예산 덱마다 따로 계산해 더한다 |
| 사용자 조정이 상한을 넘을 수 있는가 | **넘을 수 있다.** 사용자가 최종 결정권을 갖는다 (6.6) |
| 보류 복귀 카드가 신규 상한을 소비하는가 | **소비하지 않는다.** 이미 시작한 카드다. 신규 상태로 돌아와도 같다. 평가 기록에 `from_buried` 로 남겨 오늘 넣은 신규 수에서 뺀다 (I82) |

밀린 복습 상한의 근거는 인터뷰뿐이다.

> 시간적 여유가 부족하면 일부만 보고 차차 그 밀린 내역들을 해치워나가지 않을까 생각함. 초기화나 포기는 생각하지 않아.

"일부만"에 숫자가 없다. 200은 임의값이다.

### 4.7 배치

> 결정: **복습을 먼저 전부 비우고 신규로 간다.** 섞지 않는다.

```text
학습 중 → 보류 복귀 → 예정 복습 → 밀린 복습 → 신규
```

인터리빙(신규와 복습을 섞는 것)은 학습 효과 근거가 갈리고, 설명하기도 어렵다. 단순한 쪽을 택했다. 사용자가 불편을 느끼면 그때 바꾼다.

보류 복귀를 앞에 두는 이유는 이미 어려움을 겪은 카드라 집중력이 높을 때 보는 편이 낫기 때문이다.

### 4.8 참조 구현

```python
# tools/queue_reference.py
plan = build_queue(today, decks, cards, deck_ids=None, new_scale=1.0)
plan.ordered    # 실제 제시 순서
plan.summary()  # 학습 시작 전 요약 화면이 쓰는 값
plan.notes      # 사용자에게 보여줄 설명
```

## 5. 학습 시작 전 요약

화면 흐름 D1이 표시하는 값이다. 전부 `plan.summary()` 에서 나온다.

| 표시 항목 | 계산 |
|---|---|
| 복습 카드 수 | 예정 + 밀린 + 학습 중 |
| 신규 카드 수 | `len(plan.new)` |
| 밀린 복습 수 | `len(plan.backlog)` (오늘 올린 만큼) |
| 어려운 카드 재등장 수 | `len(plan.returning)` |
| 핵심 카드 수 | 전체 중 `importance = 2` |
| 분량 조정 범위 | 0배 ~ 전체. 상한을 넘어도 막지 않는다 |

## 6. 반복 루프 방지

MVP의 핵심 차별 기능이다.

### 6.1 확정된 규칙 (MVP 6.8)

- 한 카드가 같은 세션에서 두 번 Again을 받으면 어려운 카드로 분류한다
- 해당 카드를 현재 주 흐름에서 잠시 제외한다
- 다른 신규 카드와 복습 카드를 계속 진행한다
- 세션 마지막에 어려운 카드 묶음으로 다시 제시한다
- 사용자가 오늘 다시 볼지 다음 학습으로 넘길지 선택한다
- 카드를 버리지 않는다
- 보류 이유를 짧게 설명한다
- 사용자가 즉시 다시 보기로 되돌릴 수 있다

### 6.2 보류 트리거

| 항목 | 결정 |
|---|---|
| Again 2회 카운트 리셋 | 세션이 끝나면 리셋한다. `session_card_state` 에만 산다 |
| 두 Again 사이 최소 간격 | **없다.** 연속 두 번이어도 보류한다 |
| 신규와 복습에 같은 규칙인가 | **같다.** 둘 다 진도를 막는다 |
| 사용자 수동 보류도 같은 묶음인가 | **같은 묶음.** 이유만 `'user'` 로 구분한다 |

### 6.3 보류 시 SRS 상태 — 가장 중요한 결정

> **1회차 Again은 스케줄러에 넘기고, 보류를 유발한 2회차 Again은 넘기지 않는다.**
> 두 번 모두 `review_log` 에는 기록한다.

`review_log.fed_to_scheduler` 컬럼이 이 구분을 담는다.

| 방식 | 문제 |
|---|---|
| 둘 다 넘긴다 | 카드가 내일 again due로 올라와 다음 날 또 막힌다. 루프 방지가 하루짜리가 된다 |
| 둘 다 안 넘긴다 | 실패 기록이 스케줄러에서 사라져 난이도 추정이 낙관적이 된다 |
| **1회차만 넘긴다** | 실패는 반영되고, 재등장 시점은 큐가 통제한다 |

ADR 0001 7장의 경계와 일치해야 한다. **아직 ADR에서 정식 승인되지 않았다.**

### 6.4 재제시

| 시점 | 동작 |
|---|---|
| 세션 말 | 보류 묶음을 한 번에 보여준다 |
| 사용자가 "오늘 다시" | 즉시 이어서 다시 보여준다. `buried_until` 을 비운다 |
| 사용자가 "다음 학습으로" | `buried_until = 오늘 + 3일` |
| 기한 전 | 오늘 큐에 나오지 않는다 |
| 기한 후 | 보류 복귀 그룹으로 앞쪽에 배치된다 |

"오늘 다시" 는 참조 구현도 앱과 같다. `tools/queue_reference.py` 의 `bury_until(today, "today")` 는 `None` (기한 비움) 을 돌려준다.

**3일은 임의값이다.** 인터뷰의 *"계속 기억을 못하면 그냥 skip하고 아예 나중에 다시 학습"* 에 숫자가 없다.

### 6.5 사용자에게 보여줄 문구

```text
이 카드를 잠시 접어둘게요.
같은 학습에서 두 번 기억나지 않았습니다.
나머지를 먼저 끝내고 마지막에 다시 보여드릴게요.

              [지금 다시 보기]
```

세션 말이다.

```text
접어둔 카드 3장

오늘 다시 보시겠어요, 다음 학습으로 넘길까요?

        [오늘 다시]   [다음 학습으로]
```

## 7. 사용자 조정

| 조정 | 반영 |
|---|---|
| 분량 배수 | 신규 목표량에만 곱한다. 복습은 줄이지 않는다 |
| 특정 덱만 학습 | `deck_ids` 로 후보를 제한한다 (하위 덱 포함) |
| 쉬는 덱을 직접 골라 학습 | 복습만. 신규는 넣지 않는다 (4.2) |
| 여러 덱 합쳐 학습 | 예산 덱별로 계산해 이어 붙인다 |
| 설정 변경 | 다음 큐 구성부터 반영한다. 진행 중 세션은 바꾸지 않는다 |

복습을 줄이지 않는 이유는 예정된 복습을 미루면 SRS가 무너지기 때문이다. 줄일 수 있는 건 신규 투입량이다.

## 8. 엣지 케이스

전부 참조 구현의 테스트로 덮여 있다.

| 상황 | 동작 |
|---|---|
| 덱에 카드가 한 장도 없다 | 빈 큐. 오류 아님 |
| 오늘 볼 카드가 한 장도 없다 | 빈 큐 + 완료 화면 |
| 신규를 다 소진했고 목표일이 남았다 | 복습만 나온다. 목표 달성으로 표시 |
| 목표일이 오늘이다 | 당일 포함 설정에 따라 갈린다. 제외면 남은 전부 |
| 목표일이 지났다 | 남은 것을 전부 올린다 + "목표일이 지났다" |
| 남은 일수보다 신규가 훨씬 많다 | 산식대로. 상한에 걸리면 "목표일을 넘긴다"를 표시 |
| 밀린 복습이 상한의 수십 배 | 200장만. 나머지는 "차차 처리한다" |
| 가져온 직후라 전부 신규 | 정상 동작. 예산 덱 상한이 적용된다 |
| 학습 중 하루 경계를 넘었다 | 세션을 `day_rollover` 로 종료하고 새 세션. 경계 뒤 첫 평가에서 판정하고, 그 평가는 남기지 않은 채 새 날의 요약(D1)을 다시 연다 (I83) |
| 시스템 시간이 과거로 바뀌었다 | 큐는 그대로 만든다. `review_log` 는 append-only라 손상되지 않는다 |
| 세션 중 카드를 삭제했다 | 큐에서 빼고 진행. `review_log` 는 `card_id=NULL` 로 남는다 |
| 세션 중 카드의 덱을 옮겼다 | 현재 세션은 그대로. 다음 큐부터 반영 |
| 세션 중 목표일을 바꿨다 | 같음 |
| 보류 카드만 남았다 | 보류 묶음을 바로 제시한다 |
| 모든 카드가 보류되었다 | 세션 말 처리로 바로 넘어간다 |
| 여러 덱 중 한 덱만 소진 | 나머지 덱 카드로 계속 진행 |
| 하루 상한이 0이다 | 신규 0장. 복습은 정상 |
| 앱을 며칠 안 켰다 | 밀린 복습으로 쌓인다. 상한이 적용된다 |
| 덱 부모 관계가 순환하거나 유실 | 예산 덱 탐색이 자기 자신에서 멈춘다. 무한 루프 없음 |

## 9. 검증 시나리오

`tools/queue_reference.py` 의 `test()` 가 이 시나리오를 포함해 **54건**을 검사한다.

```bash
python tools/queue_reference.py                      # 테스트만
python tools/queue_reference.py <적재된.sqlite>       # 실제 데이터로 큐 구성
```

| 시나리오 | 확인하는 것 |
|---|---|
| 1. 목표일이 있는 덱의 첫 학습 | 100장 / 10일 = 10장. 핵심이 먼저 |
| 2. 반복 실패 카드가 있는 세션 | 2회 Again에 보류, 스케줄러에 안 넘김, 기한 후 복귀 |
| 3. 목표일 있는 덱 + 없는 덱 | 각각 다른 기준으로 계산되어 합산 |
| 4. 밀린 복습이 쌓인 덱 | 상한까지만, 오래된 것부터, 신규는 계속 나옴 |
| 5. 하위 덱이 많은 덱 | 상한이 합산되지 않음 (실데이터에서 발견) |

실제 컬렉션 통합 확인 결과다.

```text
학습일 2026-09-20,  카드 4,694장,  덱 140개
  복습 84   신규 100   밀린 0   핵심 20   합계 184
```

## 10. 설명 가능성

자동으로 정한 모든 수치에 이유를 붙인다. `plan.notes` 가 그것이다.

| 자동 결정 | 사용자에게 보여줄 문구 예시 |

| 목표일 경과 | `목표일이 지났다. 남은 55장 중 55장` |
