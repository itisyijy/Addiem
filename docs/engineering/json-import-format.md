# JSON 일괄 가져오기 형식

## 문서 상태

- 버전: v1
- 상태: **확정.** 참조 구현이 `tools/import_reference.py` 에 있다
- 관련: [MVP 범위 6.4.1](../product/mvp-scope.md), [데이터 모델](data-model.md)

MVP 구현 순서상 **가장 먼저 만드는 가져오기 경로**다. 이게 되면 실사용이 시작된다.

## 왜 JSON인가

작성자의 실제 워크플로가 `자료 → LLM → 카드 → 가져오기` 다. 인터뷰 진술이다.

> 외부에서 파일 작업해서 카드를 통째로 업로드 할 때도 뭔가 csv나 이런식으로 올리는데 이럴거면 json이 낫지 않나라는 생각이 있었어.

CSV는 줄바꿈과 쉼표가 든 카드에서 깨진다. 카드 본문에는 둘 다 흔하다.

## 설계 원칙

| 원칙 | 형태 |
|---|---|
| LLM이 쓰기 쉬워야 한다 | 중첩을 최소화한다. 필수 키는 두 개뿐 |
| 최소 형태가 동작해야 한다 | `front` 와 `back` 만 있으면 된다 |
| 조용히 버리지 않는다 | 실패한 항목의 위치와 이유를 전부 보고한다 |
| 부분 성공을 허용한다 | 사용자가 "성공분만 가져오기"를 고를 수 있다 |

## 최소 형태

```json
[
  { "front": "TCP와 UDP의 차이는?", "back": "TCP는 연결 지향, UDP는 비연결" },
  { "front": "OSI 7계층 중 4계층은?", "back": "전송 계층" }
]
```

배열만 있으면 된다. 전부 기본 덱으로 들어간다.

## 전체 형태

```json
{
  "deck": "정보처리기사",
  "note_type": "Basic",
  "cards": [
    {
      "front": "TCP와 UDP의 차이는?",
      "back": "TCP는 연결 지향, UDP는 비연결",
      "deck": "정보처리기사::2과목::네트워크",
      "tags": ["중요도::최우선", "기출"],
      "importance": "핵심"
    },
    {
      "front": "OSI 7계층을 나열하라",
      "back": "물리 - 데이터링크 - 네트워크 - 전송 - 세션 - 표현 - 응용"
    }
  ]
}
```

## 필드

| 키 | 위치 | 필수 | 설명 |
|---|---|---|---|
| `cards` | 최상위 | 예 | 카드 배열. 최상위가 배열이면 이것으로 본다 |
| `deck` | 최상위 | 아니오 | 기본 덱. 카드별 `deck` 이 우선한다 |
| `note_type` | 최상위 | 아니오 | 기본값 `Basic` |
| `front` | 카드 | **예** | 앞면 |
| `back` | 카드 | **예** | 뒷면 |
| `deck` | 카드 | 아니오 | `::` 로 하위 덱을 표현한다 |
| `tags` | 카드 | 아니오 | 배열 또는 공백 구분 문자열 |
| `importance` | 카드 | 아니오 | `핵심` / `일반` / `보충`. 이 카드에만 적용한다. 없으면 덱의 중요도를 따른다 |
| `note_type` | 카드 | 아니오 | `Cloze` 면 빈칸 카드, `Basic (and reversed card)` 또는 `reversed` 면 앞뒤 카드 두 장, `list` 면 목록 회상, `choice` 면 선택형. 최상위 값보다 우선한다 |
| `question` · `items` · `ordered` · `options` · `answer` · `correct` · `shuffle` · `extra` | 카드 | — | 목록 회상 · 선택형 카드만 쓴다. 아래 절 |

`::` 를 하위 덱 구분자로 쓴다. Anki 사용자에게 익숙하고, 내부 저장은 계층 테이블이다.

### 빈칸 카드 (v1.1)

`front` 에 `{{c1::...}}` 가 있거나 `note_type` 이 `Cloze` 면 빈칸 카드다. 빈칸 번호마다 카드가 한 장씩 생긴다. `back` 은 답을 본 뒤 보이는 추가 설명이고 생략할 수 있다.

```json
{ "front": "TCP는 {{c1::연결 지향}}, UDP는 {{c2::비연결}} 프로토콜이다" }
```

### 목록 회상 · 선택형 (v1.2)

앱 전용 노트 유형(DECISIONS Q10)으로 들어간다. 노트 하나에 카드 한 장. `front` · `back` 대신 아래 키를 쓴다. `deck` · `tags` · `importance` 는 다른 카드와 같다.
`note_type` 이 `list` · `choice` 이거나, 없으면 `items` 키가 있으면 목록 회상, `options` 키가 있으면 선택형이다.

| 키 | 목록 | 선택형 | 설명 |
|---|---|---|---|
| `question` | **필수** | **필수** | 질문. HTML 을 쓸 수 있다 |
| `items` | **필수** | | 항목 글자 배열. 2개 이상. 빈 글자는 빼고 센다 |
| `ordered` | 선택 | | `true`(기본) = 순서대로, `false` = 순서 없이 |
| `options` | | **필수** | 보기 글자 배열. 빈 글자는 빼고 2–6개 |
| `answer` | | `answer` · `correct` 중 **하나만** | 정답 보기 글자 (v1.3). `options` 의 글자와 앞뒤 공백만 빼고 **정확히 같아야** 한다 (대소문자 · 띄어쓰기 · 문장부호 그대로). 하나면 `"SYN-ACK"`, 여럿이면 `["TCP", "UDP"]`. **AI 가 만드는 파일은 이쪽을 권한다** (번호를 0부터 세는 실수가 없다) |
| `correct` | | `answer` · `correct` 중 **하나만** | 정답 보기 번호. **1부터** 센다(화면의 ①②와 같다). 하나면 `2`, 여럿이면 `[1, 3]`. 0부터 세면 정답이 하나씩 밀려도 알 수 없다 |
| `shuffle` | | 선택 | `true`(기본) = 학습할 때 보기를 섞는다 |
| `extra` | 선택 | 선택 | 추가 설명 · 해설. HTML 을 쓸 수 있다 |

항목과 보기는 글자로 저장한다. `<b>` 같은 태그를 써도 그 글자 그대로 보인다.

```json
[
  { "question": "OSI 7계층을 아래에서부터", "items": ["물리", "데이터 링크", "네트워크", "전송", "세션", "표현", "응용"] },
  { "question": "TCP 3-way 핸드셰이크의 두 번째 패킷은?", "options": ["SYN", "SYN-ACK", "ACK"], "answer": "SYN-ACK",
    "extra": "서버가 SYN 을 받고 보내는 응답이다" },
  { "question": "전송 계층 프로토콜을 모두 고르면?", "options": ["TCP", "IP", "UDP", "모두 아님"], "answer": ["TCP", "UDP"], "shuffle": false }
]
```

번호로 쓰려면 `"answer"` 대신 `"correct": 2` · `"correct": [1, 3]` 이다 (1부터).

### 태그와 중요도

태그는 카드가 아니라 **하위 덱의 중요도 제안**으로 모은다. 새로 만든 하위 덱에서 카드 절반 이상이 같은 중요도 태그(`중요도::최우선` 등)를 달고 있으면 그 덱을 그 중요도로 제안하고, 사용자가 B4 화면에서 확정한다. 태그가 없으면 덱 이름(`요약`, `부록` 등)으로 제안한다. 이미 있던 덱의 중요도는 바꾸지 않는다.

## 검증 규칙

| 상황 | 처리 |
|---|---|
| `front` 또는 `back` 이 없다 | 해당 항목만 건너뛰고 **몇 번째인지 보고한다**. 빈칸 카드는 `back` 이 없어도 된다 |
| 빈칸 카드인데 `{{c1::...}}` 가 없다 | 건너뛰고 보고한다 |
| `front` 또는 `back` 이 빈 문자열 | 같음 |
| 목록 · 선택형의 키가 없거나 형식이 틀리다 (`items` 가 배열이 아니다, `ordered` 가 true/false 가 아니다 등) | 건너뛰고 보고한다 |
| 목록 · 선택형이 앱의 저장 규칙에 맞지 않다 (항목 2개 미만, 보기 2개 미만 · 7개 이상, 정답 없음) | 건너뛰고 보고한다. 앱에서 카드를 저장할 때와 같은 검사 · 같은 문구다 |
| `correct` 가 없는 보기나 빈 보기를 가리킨다, 0 이나 숫자가 아니다 | 건너뛰고 보고한다. 앱 화면과 달리 조용히 버리지 않는다 |
| `answer` 와 `correct` 가 둘 다 있다 | 건너뛰고 보고한다 (`bad_field`). 둘이 어긋날 수 있어 어느 쪽도 고르지 않는다 |
| `answer` 글자와 같은 보기가 없다 · 같은 보기가 여러 개다 · 글자가 아니다 | 건너뛰고 어느 글자인지 보고한다 |
| `front` 가 중복된다 | 가져오되 경고로 보고한다. 의도적인 경우가 있다. 목록 · 선택형은 `question` 으로 본다 |
| `importance` 값이 잘못됐다 | 무시하고 추론으로 넘어간다. 경고 |
| 최상위가 배열도 객체도 아니다 | 전체 실패 |
| `cards` 가 비어 있다 | 전체 실패. "가져올 카드가 없다" |

**항목 하나가 잘못됐다고 전체를 버리지 않는다.** LLM이 만든 수백 장 중 한 장이 깨지는 일은 흔하다.

## 결과 보고

```text
가져오기 완료

  가져옴      312장
  건너뜀        3장
  경고          1건

건너뛴 항목
  #47   back 이 비어 있다
  #128  front 키가 없다
  #201  front 이 문자열이 아니다

경고
  #88   importance 값 '매우중요' 를 알 수 없다. 태그로 추론했다
```

MVP 6.4의 "조용히 삭제하거나 변환하지 않는다" 원칙을 따른다.

## 사용

앱에서는 `가져오기 → JSON` 에 붙여넣거나 파일을 고른다. 가져오기 전에 몇 장이 들어가고 무엇을 건너뛰는지 먼저 보여준다. 구현은 `src-tauri/src/import.rs` 다.

참조 구현(빈칸 카드, 목록 · 선택형, 덱 단위 태그 제안은 없다):

```bash
python tools/import_reference.py cards.json out.sqlite
```
