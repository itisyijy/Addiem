## 0. 이 문서의 나머지에 대하여

v0.1에서는 1장만 채우고 2장 이하를 비워두었다. 화면별 브리프는 코드로 대신하는 편이 낫다고 봤기 때문이다.

v0.2에서 2장 이하를 채웠다. 화면을 Figma로 먼저 그렸고, 그 과정에서 내린 결정을 여기에 옮겼다. **화면이 정본이고 이 문서는 결정의 기록이다.** 둘이 다르면 Figma를 기준으로 이 문서를 고친다.

화면별 결정 노트는 Figma의 각 프레임 아래에도 같은 내용으로 붙어 있다.

## 1. 선행 결정. 홈 정보 우선순위

다른 화면을 그리기 전에 이것부터 정한다.

화면 흐름 10장이 정한 네 가지 질문에 답한다.

| 질문 | 답 | 홈에서 어떻게 표현하는가 |
|---|---|---|
| 오늘 무엇을 공부해야 하는가 | 전체 합계 한 숫자 | 화면 최상단. `오늘 184장` 처럼 가장 큰 글자 |
| 어느 덱에서 얼마나 남았는가 | 덱별 잔여 수 | 합계 아래 목록. 오늘 볼 카드가 있는 덱만 |
| 어디를 눌러 바로 시작하는가 | 전체 학습 버튼 하나 | 합계 바로 아래. 화면에서 가장 큰 버튼 |
| 새 덱이나 Anki 덱은 어디서 추가하는가 | 부차적 위치 | 상단 모서리 또는 목록 하단. 학습 시작과 경쟁하지 않게 |

> v0.2 변경: 덱 목록 위치를 "합계 아래"에서 "오른쪽 열"로 옮겼다. 6장 리뷰 기록 참고.

### 정보 위계

| 순위 | 요소 | 이유 |
|---|---|---|
| 1 | 오늘 학습할 총 카드 수 | 사용자가 앱을 켠 이유가 이것 하나다 |
| 2 | 학습 시작 버튼 | 결정 없이 바로 시작할 수 있어야 한다 |
| 3 | 덱별 잔여 수 | 특정 덱만 하고 싶을 때 쓴다 |
| 4 | 목표일이 임박한 덱의 경고 | 행동을 바꾸는 정보다 |
| 5 | 덱 추가 / 가져오기 | 매일 쓰는 기능이 아니다 |

**숫자 하나를 크게 보여주되 압박을 주지 않는다.** 인터뷰에서 확인된 문제다.

> 사용자는 앱을 켰을 때 "오늘 복습할 카드 수"를 보고 압박감을 느낀다.

그래서 밀린 카드를 합계에 섞지 않는다. 큐가 이미 상한으로 잘라서 올리므로, 홈에 보이는 숫자는 **오늘 실제로 할 분량**이다. 밀린 총량은 덱을 펼쳤을 때만 보여준다.

### 홈의 성격

> **홈은 오늘의 학습 화면이다. 덱 목록이 아니다.**

레이아웃에서 이렇게 드러난다.

- 화면을 열었을 때 가장 먼저 보이는 것이 덱 이름 목록이 아니라 **오늘의 숫자와 시작 버튼**이다
- 덱 목록은 그 아래에 있고, 덱 관리 기능(이름 변경, 보관, 삭제)은 홈에 없다. 덱 상세로 들어가야 한다
- 덱이 하나도 없을 때만 홈이 덱 생성 화면처럼 보인다

### 덱이 여러 개일 때

실측 컬렉션이 최상위 7개, 전체 140개였다. 하위 덱까지 홈에 나열하면 화면이 무너진다.

| 상황 | 표현 |
|---|---|
| 덱이 1개 | 합계와 덱 수가 같으므로 덱 목록을 생략한다 |
| 덱이 3개 | 전부 나열한다 |
| 덱이 20개 | **오늘 볼 카드가 있는 덱만** 나열한다. 나머지는 "그 외 N개"로 접는다 |
| 오늘 볼 카드가 없는 덱 | 목록에서 뺀다. 접힌 영역에만 둔다 |
| 목표일이 임박한 덱 | 목록 위로 올리고 남은 일수를 붙인다 |
| 하위 덱 | **홈에 펼치지 않는다.** 최상위 덱 단위로만 합산해 보여준다 |

마지막 항목이 실데이터에서 나온 규칙이다. 하위 덱을 펼치면 140줄이 된다.

## 2. 공통 규칙

### 이번 작업에서 결정하지 않는 것

화면 흐름 9장에서 이미 제외된 항목이다. 여기에 시간을 쓰지 않는다.

- 최종 색상과 타이포그래피
- 브랜드 로고
- 카드 유형 전체 구조
- 상세 SRS 간격 표시 방식
- 고급 통계 차트
- 모바일 레이아웃
- 협업과 공유 흐름
- AI 기능 UI

색과 글꼴은 **임시 테마**로 그렸다. 전부 Figma 변수(`Addiem Color`)와 텍스트 스타일에 묶여 있어서 값만 바꾸면 화면 전체가 따라 바뀐다. 최종 결정이 아니다.

### 이번 작업에서 지킬 것

| 항목 | 결정 |
|---|---|
| 도구 | Figma. 화면, 컴포넌트, 사용자 흐름 보드, 클릭 프로토타입이 한 파일에 있다 |
| 화면 기준 해상도 | 1280×800 데스크톱 창. 스크롤 분량을 보여줄 때만 높이 860~900 |
| 충실도 수준 | 중충실도. 실제 문구와 실측 데이터 규모(4,694장, 140개 덱)로 채우고, 색·글꼴은 교체 가능한 임시값 |
| 실제 문구 사용 여부 | 실제 문구를 쓴다. 더미 텍스트를 쓰지 않는다 |
| 화면당 주 행동 개수 | 1개 |

### 공통 문구 결정

| 내부 용어 | 화면 문구 | 이유 |
|---|---|---|
| 보류 (bury) | **접어두기 / 접어둔 카드** | "보류"는 버린다는 어감이 있다. 접어둔 것은 다시 펼친다 |
| 큐 | 오늘의 학습 | 신규 사용자는 큐를 모른다 |
| 세션 종료 | 그만하기 | 중단이 실패처럼 들리지 않게 |

## 3. 화면별 브리프

각 화면의 필수 요소는 화면 흐름 문서에서 이미 확정된 내용이다.

### 3.1 빈 홈 (A1)

| 항목 | 내용 |
|---|---|
| 목적 | 새 덱을 만들거나 Anki 덱을 가져온다 |
| 필수 요소 | `새 덱 만들기`, `Anki 덱 가져오기` |
| 가장 강한 행동 | 두 행동을 같은 무게로 둔다. 사용자 유형을 묻지 않는 대신 첫 화면에서 두 갈래를 동등하게 보여준다 |
| 두 행동의 시각적 무게 차이 | 같은 크기의 카드 두 장. 기본 포커스만 새 덱 쪽(진한 테두리, 채운 아이콘). 단축키 N / I 표시 |
| 설명 문구를 넣는가 | 헤드라인 1줄 + 보조 1줄. 위에 "모든 데이터는 이 기기에만 저장돼요" pill (local-first 신뢰 신호) |
| 넣지 않을 것 | 강제 온보딩, 긴 설명 |

Figma: `A1 빈 홈`

### 3.2 사용 중인 홈 (A2)

| 항목 | 내용 |
|---|---|
| 목적 | 오늘 학습할 것을 확인하고 바로 시작한다 |
| 필수 요소 | 오늘 남은 전체 카드 수, 덱별 오늘 학습량, `오늘 학습 시작`, 덱 목록, 새 덱 추가 |
| 가장 강한 행동 | `오늘 학습 시작` (Enter). 숫자 바로 아래, 화면에서 유일한 채운 버튼 |
| 오늘 할 것이 없을 때의 표시 | 숫자 자리를 "오늘 남은 카드 0장"이 차지한다. 내일 예정량 한 줄, 보조 버튼 두 개(카드 추가, 접어둔 카드 보기). `A2-b 오늘 학습 끝` |
| 덱별 학습량을 어떤 단위로 보여주는가 | 덱마다 합계 장 수 + "복습 n · 신규 n" 한 줄. 행마다 그 덱만 학습하는 `학습` 버튼 |
| 어려운 카드 수를 여기서 보여주는가 | 보여주지 않는다. 덱 상세와 학습 완료 화면에서 다룬다 |

추가 결정: 숫자 아래에 복습/신규 구성 막대를 둔다. 비율만 보여주고 경고색은 쓰지 않는다.

Figma: `A2 사용 중인 홈`, `A2-b 오늘 학습 끝`

### 3.3 새 덱 만들기 (B1)

| 항목 | 내용 |
|---|---|
| 목적 | 이름 하나만 받고 즉시 통과시킨다 |
| 필수 입력 | 덱 이름 |
| 완료 후 이동 | 빈 덱 상세 |
| 화면 형태 | 홈 위 모달. 열리자마자 입력에 포커스, Enter로 만들기, Esc로 취소 |
| 이름 외의 선택 항목을 노출하는가 | 노출하지 않는다. 헬퍼 문구로 "목표일과 학습 설정은 나중에 덱 안에서 정할 수 있어요"만 알린다 |
| 넣지 않을 것 | 시험 유형, 목표일, 사용자 유형 설문, 설정 마법사 |

같은 부모 아래 같은 이름이면 입력 아래 인라인 오류 (스키마 `UNIQUE(parent_id, name)`).

Figma: `B1 새 덱 만들기`

### 3.4 덱 상세 (C1)

| 항목 | 내용 |
|---|---|
| 목적 | 덱 상태를 이해하고 바로 학습을 시작한다 |
| 필수 요소 | 덱 이름, 오늘 학습량, 신규/복습 카드 수, 아직 보지 않은 카드 수, 어려운 카드 수, 목표일까지 남은 날짜, `학습 시작`, `카드 보기`, `목표 및 학습 설정` |
| 가장 강한 행동 | 어두운 "오늘" 카드 안의 `학습 시작`. 화면에서 유일하게 반전된 면이라 시선이 먼저 간다 |
| 카드가 0장인 빈 덱 상태 | 숫자를 0으로 채우지 않고 빈 상태 하나와 행동 두 개(`첫 카드 추가`, `JSON으로 가져오기`). `C1-a 빈 덱 상세` |
| 목표일이 없을 때 그 자리에 무엇을 두는가 | 점선 제안 카드: "목표일 없이 꾸준히 반복하는 덱이에요" + `목표일 정하기`. `C1-b 덱 상세 · 목표일 없음` |
| 목표 설정을 언제 제안하는가 | 카드가 20장 이상이 되었거나 첫 학습을 마친 뒤. 목표 카드 자리에서만 제안하고 팝업·배너로 반복하지 않는다 |
| 숫자 6개를 어떻게 묶어 보여주는가 | 세 묶음. 오늘(72 = 복습 32 + 신규 40) / 목표(D-12, 본 카드 %, 핵심 카드 학습률 %) / 덱 전체(아직 보지 않은 카드, 어려운 카드, 밀린 복습) |

추가 결정:

- 오늘 분량 아래에 계산 근거를 한 줄로 붙인다. `남은 신규 480장 ÷ 12일 = 하루 40장`
- 밀린 복습 총량은 홈이 아니라 여기서만 보여준다
- 중요도 요약 띠(핵심/일반/보충 장 수 + 확인하지 않은 제안 수)에서 `중요도 조정`으로 들어간다
- 덱 관리(이름 변경, 보관, 삭제)는 ⋯ 메뉴

Figma: `C1 덱 상세`, `C1-a 빈 덱 상세`, `C1-b 덱 상세 · 목표일 없음`

### 3.5 카드 추가 (C3)

| 항목 | 내용 |
|---|---|
| 목적 | 새 덱을 만든 직후 첫 카드를 바로 넣는다 |
| 필수 요소 | 카드 유형, 질문 또는 본문, 답변, 이미지 첨부, 중요도, 저장 |
| 기본값 | 질문과 답변, 중요도 일반 |
| 연속 입력을 지원하는가 | 지원한다. "저장 후 바로 다음 카드"가 기본으로 켜져 있다 |
| 저장 후 어디로 가는가 | 같은 화면. 폼을 비우고 질문에 포커스, 방금 추가한 카드가 오른쪽 목록에 쌓인다. 학습으로 가는 길은 헤더의 `추가 끝내고 학습 시작` 하나 |
| 빈칸 카드일 때 폼이 어떻게 바뀌는가 | 질문/답변 두 칸이 본문 한 칸으로 합쳐지고, 답변 자리는 선택 사항인 "추가 설명"이 된다. 단어를 선택하고 `빈칸 만들기`(Ctrl Shift C). 만들어질 카드 수를 배지로 보여준다. Cloze 문법은 노출하지 않는다 |
| 중요도를 얼마나 눈에 띄게 둘 것인가 | 폼 아래쪽 3단 세그먼트. 비워두면 하위 덱 설정을 따른다는 문구를 함께 둔다 |

오른쪽 미리보기는 학습 화면과 같은 위계로 렌더링한다. 긴 답변이 어떻게 보일지 작성 중에 확인할 수 있다.

Figma: `C3 카드 추가`, `C3-b 카드 추가 · 빈칸`

### 3.6 학습 시작 전 요약 (D1)

| 항목 | 내용 |
|---|---|
| 목적 | 오늘 무엇을 왜 보여주는지 이해시키고 분량을 조정하게 한다 |
| 필수 요소 | 복습 카드 수, 신규 카드 수, 핵심 카드 수, 어려운 카드 재등장 수, 분량 조정, `학습 시작` |
| 가장 강한 행동 | `학습 시작` (Enter) |
| 계획 근거를 한 문장으로 어떻게 쓰는가 | 목록 머리에 한 문장: "빅데이터분석기사 시험이 12일 남아 핵심 신규를 먼저 넣었어요." 숫자 근거는 각 행의 회색 문구로 (`남은 480장 ÷ 12일`) |
| 분량 조정 조작 방식 | 세 단계 프리셋 `가볍게 50` / `권장 100` / `더 많이 150` (0.5× / 1× / 1.5×). 신규에만 적용된다는 문구를 바로 아래 고정 |
| 이 화면을 건너뛸 수 있게 하는가 | 허용한다. 기본은 보여주고, "다음부터 바로 시작" 체크박스로 끈다 |

레이아웃: 왼쪽은 "얼마나"(총합, 구성 막대, 분량 조정), 오른쪽은 "어떤 순서로, 왜"(큐 배치 순서 5단계: 접어둔 카드 → 복습 → 핵심 → 일반 → 보충 신규).

이 화면이 Addiem과 Anki의 차이를 사용자가 처음 체감하는 지점이다.

### 3.7 질문과 답변 및 평가 (D2, D3)

| 항목 | 내용 |

## 4. 흐름 연결 확인

각 화면이 아니라 이어짐을 검토한다. Figma 프로토타입에서 시작점 `1 신규 사용자`로 직접 눌러볼 수 있다.

```text
빈 홈
→ 새 덱 만들기
→ 빈 덱 상세
→ 카드 추가
→ 학습 시작 전 요약
→ 질문
→ 답변과 평가
→ 학습 완료
→ 사용 중인 홈
```

| 전환 | 사용자가 누르는 것 | 되돌아갈 수 있는가 |
|---|---|---|
| 빈 홈 → 새 덱 만들기 | `새 덱 만들기` 카드 또는 N | 있다. 취소 / Esc |
| 새 덱 만들기 → 덱 상세 | `만들기` 또는 Enter | 있다. `← 홈`. 덱은 이미 만들어진 상태다 |
| 덱 상세 → 카드 추가 | `첫 카드 추가` 또는 A | 있다. `← 덱` |
| 카드 추가 → 학습 시작 전 요약 | `추가 끝내고 학습 시작` | 있다. `← 홈` |
| 학습 시작 전 요약 → 질문 | `학습 시작` 또는 Enter | 있다. `그만하기`(Esc)는 중간 종료 화면(D5-b)으로 간다 |
| 답변과 평가 → 다음 질문 | 평가 버튼 또는 1–4 | 없다. 평가는 바로 기록된다. 실행 취소는 MVP 범위 7장 Should |
| 답변과 평가 → 학습 완료 | 마지막 카드 평가 | 없다. 같은 학습일 안에서는 이어하기로 다시 들어온다 |
| 학습 완료 → 홈 | `다음 학습으로 넘기기` 또는 `홈으로` | - |

## 5. 검증 질문

화면 흐름 8장의 질문이다. 아래 "통과"는 **설계자의 자체 점검**이다. 실제 사용자 테스트로 다시 확인해야 한다.

| 질문 | 통과 | 메모 |
|---|---|---|
| 처음 실행한 사용자가 다음 행동을 즉시 알 수 있는가 | 설계상 통과 | 빈 홈에 행동이 카드 두 장뿐이다 |
| 덱 이름만 입력하고 바로 카드 추가로 넘어갈 수 있는가 | 설계상 통과 | 모달 → Enter → 빈 덱 상세의 `첫 카드 추가`. 클릭 2번 |
| 덱 상세에서 학습 시작이 가장 강한 행동으로 보이는가 | 설계상 통과 | 화면에서 유일한 반전 면 안의 유일한 채운 버튼 |
| 사용자가 오늘 학습량의 구성을 이해할 수 있는가 | 확인 필요 | D1의 5단계 순서 목록이 이해되는지는 신규 사용자 테스트가 필요하다 |
| 복습 중 질문, 답 확인, 평가가 빠르게 이어지는가 | 설계상 통과 | Space → 1–4. 버튼 위치가 같은 높이 |
| 세션 종료 후 어려운 카드가 별도로 남아 있음을 이해할 수 있는가 | 확인 필요 | 세션 중 칩과 완료 화면 목록으로 보여주지만 "3일 뒤"가 납득되는지는 실사용으로 본다 (큐 명세 D2: 근거 약함) |
