# Neo-Anki UI 문구 기준

앱 화면에 나오는 문구는 이 기준을 따른다. 근거와 화면별 피드백은 [UI 문구 이해도 검토](ui-copy-review.md)(2026-10-15) 8장에 있다. 새 화면을 만들거나 문구를 고칠 때는 아래 표의 권장 표기를 먼저 쓰고, 바꿔야 하면 이 문서를 함께 고친다.

## 공통 용어

| 개념 | 권장 표기 | 사용 규칙 |
|---|---|---|
| Deck | 덱 | 첫 빈 홈에서만 ‘학습 카드를 모아 두는 묶음’으로 설명한다. 과목·폴더를 무조건 덱과 동의어로 쓰지 않는다. |
| Note / Card | 노트 / 카드 | 초보에게는 ‘같은 내용에서 만들어진 카드들(Anki 노트)’로 설명한다. 입력 항목 수·노트 수·생성 카드 수의 단위를 바꾸지 않는다. |
| New | 신규 카드 / 아직 학습하지 않은 카드 | 짧은 목록은 ‘신규’, 첫 안내는 풀어서 쓴다. 다시 가져와 신규로 시작하는 경우 원래 처음 본 자료라는 뜻으로 오해하지 않게 설명한다. |
| Review | 복습 | 예정일이 지난 복습은 ‘밀린 복습’. 앞면 공개를 ‘복습 완료’로 단정하지 않는다. |
| Importance | 중요도 · 핵심 / 일반 / 보충 | 우선순위와 숙달 정도를 구분한다. 보충을 학습 제외로 표현하지 않는다. |
| Buried | 접어두기 | 실제 복귀 날짜를 함께 쓴다 (예: ‘3일 뒤 다시 보기 · 10월 18일 (토)부터 오늘의 학습에 다시 포함돼요’). ‘다음’이나 ‘나중’만으로 기간을 설명하지 않는다. |
| Suspended | 카드 학습 중지 | 덱 보관·기간 있는 접어두기와 구분한다. |
| Paused deck | 덱 학습 쉬기 / 다시 시작 | 기간과 자동 재개일을 함께 표시한다. 목표일이 유지된다는 설명을 가까이 둔다. |
| Archived deck | 덱 보관 / 보관 해제 | ‘되살리기’ 대신 저장 상태의 변화를 직접 표현한다. |
| Weak chapter | 취약 챕터 / 취약 챕터 제안 | 사용자 확정(지정)과 통계 기반 제안을 구분한다. |
| Mastery / progress | 학습 시작 비율 / 회독 진행률 | 실제 측정값만 이름에 넣는다. 숙달·정답률·시험 준비도와 섞지 않는다. |
| Source | 학습 자료 / 연결 자료 / 원자료 파일 | 탐색·카드 옆 열기·파일 전체의 전송 설명에 각각 쓴다. |
| Keyword | 핵심어 | ‘필수 키워드’와 ‘핵심어’를 섞지 않고 등록·제안·확인 상태를 구분한다. |
| AI splitting | 비슷한 내용끼리 나누기 (ChatGPT) | 로컬 규칙 분할·로컬 분석 모델·외부 AI 요청을 같은 ‘모델’로 부르지 않는다. 로컬 모델은 ‘분석 모델’이다. |
| Concept check (8.3) | 개념 관계 / 개념 관계 확인 모델 | 서술형 답의 관계(원인 → 결과 등)를 기기 안의 작은 언어 모델로 살펴보는 실험 기능. 임베딩 ‘분석 모델’과 섞지 않게 모델은 ‘개념 관계 확인 모델’로 부른다. 결과에는 ‘참고’를 붙이고 정확하다고 쓰지 않는다. 판정 낱말은 맞음 · 빠짐 · 거꾸로 · 부정 · 틀림. |
| Sync / Backup / Restore | 동기화 / 백업 / 백업으로 복구 | 현재 상태 맞추기·시점 보관·시점 복구를 구분한다. 평가 취소는 ‘마지막 평가 되돌리기’로 유지한다. |
| Counts | 카드 n장 / 노트 n개 / 평가·변경 n회·n건 / 자료 구간 n곳 | 합계와 세부 항목의 분모·집계 기간을 일치시킨다. |
| Note type | 노트 유형 | ‘노트 타입’·‘템플릿’과 섞지 않는다. 처음 보는 곳(설정 칸 머리)에서는 ‘카드를 만드는 틀’로 설명한다. |
| Field | 필드 | 카드 추가 화면의 칸 이름은 필드 이름 그대로 쓴다. 필드를 지우는 행동은 ‘필드 지우기’, 확인 창에 내용은 숨긴다는 사실을 쓴다. |
| Card template | 카드 종류 | 템플릿 하나 = 카드 종류 하나. 이름은 ‘카드 1 · 단어 → 뜻’ 꼴. ‘템플릿’은 HTML 탭 안내에서만 쓴다(‘이 템플릿은 HTML로만 고칠 수 있어요’). |
| Front / Back | 앞면 / 뒷면 | 학습 화면의 ‘질문 면 / 답 면’과 같은 뜻이다. 편집기에서는 앞면·뒷면으로 통일한다. |
| Stock / imported / custom type | 앱 기본 유형 / Anki에서 가져온 유형 / 내가 만든 유형 | 앱 기본 유형은 ‘볼 수만 있어요 · 복제하면 고칠 수 있어요’로 설명한다. 그림 가리기·목록·선택형은 ‘앱이 직접 그리는 유형’이다. |
| Editor modes | 쉬운 편집 / HTML | 탭 이름. ‘고급’·‘개발자’ 같은 말을 붙이지 않는다. |
| Type suggestion | 유형 추천 | 칩은 ‘이유 한 줄 + [○○으로 바꾸기]’. 이유는 센 사실만 쓴다(‘번호 붙은 줄이 5개예요’). |
| Deck update import | 업데이트로 가져오기 / 새 노트만 더하기 | 이미 가져온 덱의 새 파일을 받을 때 고르는 두 방식이다. ‘덮어쓰기’·‘동기화’라고 하지 않는다. 권장 방식에만 ‘권장’ 배지를 붙인다. |
| Deck author | 만든 사람 | 덱 파일을 만들어 나눠 준 사람. ‘작성자’·‘제작자’와 섞지 않는다. |
| Base / mine / theirs | 원본 / 내 것 / 새 버전 | 원본은 비교 기준이라 화면에는 ‘지난번에 받은 버전’으로 쓴다(받은 시각은 저장하지 않아 날짜를 붙이지 않는다). 내 것 = 지금 내 덱, 새 버전 = 이번 파일. ‘로컬·원격·업스트림’을 쓰지 않는다. 가져온 파일 자체를 뜻하는 ‘원본 파일’과 겹치므로, 원본은 ‘비교할 원본이 없는 노트’처럼 비교 기준을 말할 때만 쓴다. |
| Update outcomes | 새 버전으로 바뀌는 노트 / 합친 노트 / 충돌 / 내가 고쳐 지키는 노트 | 합친 노트 = 한 노트 안에서 만든 사람이 고친 필드는 새 버전, 내가 고친 필드는 내 것. 충돌 = 같은 필드를 둘 다 고친 노트. 고르지 않으면 ‘내 것을 지켜요’, 고른 것은 ‘충돌한 필드에만 적용돼요’로 쓴다. |
| Card look conflict | 내 모양 / 새 모양 | 카드 종류(앞면 · 뒷면 · CSS) 비교에만 쓴다. 노트 내용 비교의 내 것 / 새 버전과 섞지 않는다. 버튼은 [내 모양 유지] [새 모양으로]. |
| Notes not in update | 새 버전에 없는 노트 / 내가 지운 노트 | ‘삭제된 노트’라고 하지 않는다. 새 버전에 없는 노트는 지우지 않고 학습에도 나온다고 함께 쓴다. 내가 지운 노트는 ‘다시 넣지 않아요’. |

## 톤과 배치

- 문장 톤은 해요체를 유지한다.
- ‘허용되지 않아요’보다 할 수 있는 다음 행동을 구체적으로 쓴다.
- ‘그대로·모두·바로·언제든’은 실제 적용 범위가 확인될 때만 쓴다.
- 설명을 늘릴 때는 **짧은 버튼명 → 바로 아래(또는 옆)의 결과 설명 한 줄 → 필요할 때 여는 상세 도움말** 순서로 배치한다. 버튼에 설명을 넣어 길게 만들지 않는다.
- 중요한 기간·영향 범위는 툴팁에만 숨기지 않는다.
- 숫자와 날짜는 실제 데이터로 채운다. 화면 예시 숫자를 그대로 두지 않는다.
- 개인 학습 화면에 제품 검증용 기준(합격선 같은 판정)이나 내부 문서 참조를 넣지 않는다. 실제 측정값과 그 정의만 보여 준다.

## 이미 잘 쓰고 있는 표현 (유지)

B1의 덱 이름 입력과 나중에 목표를 정할 수 있다는 안내, B2-0의 Anki 내보내기 경로, D3-u의 ‘복습 일정도 원래대로예요’, C1 메뉴의 하위 덱 동반 삭제 안내, 수식 오류의 위치·저장 가능 여부 안내, AI 초안의 승인 전 미생성 안내.
